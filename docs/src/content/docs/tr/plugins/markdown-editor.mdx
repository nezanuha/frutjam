Form gönderimi, doğrulama ve gerekli alanların çalışmaya devam etmesi için metin alanınızı değiştirmek yerine geliştiren bir işaretleme düzenleyicisi. WYSIWYG ve düz Markdown modları, canlı önizleme, bul ve değiştir, RTL desteği, karanlık mod. Django, Laravel, Rails, Node.js, PHP ve herhangi bir yığınla bağımsız olarak çalışır.

**Frutjam ve Tailwind gerekmez.** Stiller paket halinde olduğundan editör herhangi bir projeye dahil olur.

## MarkdownEditor vs EasyMDE / SimpleMDE

Çoğu JavaScript işaretleme düzenleyicisi (EasyMDE, SimpleMDE, CodeMirror tabanlı düzenleyiciler) ** `<textarea>`** ve form gönderildiğinde içeriği geri yazarak bir kopyasını düzenleyin. Bu, başka bir şeyin değere ihtiyacı olana kadar işe yarar: a `required` tarayıcının odaklanamadığı alan gönderimi tamamen engeller ve `.value` veya `FormData` göndermeden önce oku, htmx, Turbo, otomatik kaydetme ve kaydedilmemiş değişiklik korumalarını bozan boş bir dize döndürür. **MarkdownEditor farklıdır.** Zaten sahip olduğunuz textarea'yi şekillendirir ve onu yazdığınız alan olarak bırakır, böylece değer her an doğru olur.

## Çerçeve Entegrasyonu

**MarkdownEditor** yerel içeriği koruduğu için `<textarea>`, herhangi bir ekstra kod olmadan her arka uç çerçevesiyle bütünleşir. Sunucunuz işaretleme içeriğini tam olarak herhangi bir standart form alanından aldığı gibi alır. React ve Vue için bu bölümün sonunda ele alınan birkaç satır gerekir.

### Django

Ekle `class` textarea widget'ınıza gidin ve düzenleyiciyi başlatın: `request.POST['content']` ekstra adım gerektirmeden çalışır.

<Snippet view="code">

```python
# forms.py
class PostForm(forms.ModelForm):
    class Meta:
        model = Post
        fields = ['content']
        widgets = {
            'content': forms.Textarea(attrs={'class': 'markdown-editor'}),
        }
```

</Snippet>

<Snippet view="code">

```javascript
new MarkdownEditor('.markdown-editor');
// request.POST['content'] contains the markdown on submit
```

</Snippet>

### Laravel

Kullanmak `f.text_area` bir sınıfla: `$request->input('content')` indirimi doğrudan alır.

<Snippet view="code">

```html
<textarea name="content" class="markdown-editor">{{ old('content') }}</textarea>
<script>new MarkdownEditor('.markdown-editor');</script>
```

</Snippet>

### Ruby on Rails

İle çalışır `form_with` kutunun dışında: `params[:content]` işaretlemeyi içerir. Turbo Tahrik için şunu kullanın: `turbo:load` yerine `DOMContentLoaded`.

### Tepki ver

Düzenleyiciyi bir efektte oluşturun ve bağlantıyı kestiğinizde onu yok edin. Kullanmak `defaultValue` yerine `value`: Düzenleyici doğrudan textarea'ya yazar, böylece kontrollü bir ciltleme kullanıcının yazdıklarının üzerine yazar.

<Snippet view="code">

```javascript
import { useEffect, useRef } from 'react';
import MarkdownEditor from 'markdown-text-editor';

function MarkdownField({ name, defaultValue = '', onChange }) {
    const ref = useRef(null);

    // Options are read once at construction, so the editor would hold on to
    // whichever onChange it was handed first. A ref keeps it current.
    const onChangeRef = useRef(onChange);
    onChangeRef.current = onChange;

    useEffect(() => {
        const editor = new MarkdownEditor(ref.current, {
            onChange: (value) => onChangeRef.current?.(value),
        });
        return () => editor.destroy();
    }, []);

    return &lt;textarea ref={ref} name={name} defaultValue={defaultValue} /&gt;;
}
```

</Snippet>

Geri dönüyor `editor.destroy()` Bu efekt aynı zamanda geliştirme aşamasında efektleri iki kez çalıştıran ve aksi takdirde iki editörün bir metin alanında kalmasına neden olan StrictMode'u da kapsar. Boş bağımlılık dizisi kasıtlıdır: seçenekler düzenleyici oluşturulduğunda bir kez okunur, bu nedenle efektin yeniden çalıştırılması onu yıkıp her oluşturmada yeniden inşa etmesine neden olur.

Bu yüzden de `onChange` bir hakemden geçiyor. Doğrudan yapıcıya iletmek, düzenleyiciyi montaj sırasında aldığı işleve sabitleyecektir ve ebeveyndeki satır içi ok, değiştiğinde kapattığı herhangi bir şey anında eskiyecektir.

### Vue

Aynı fikir. Başlangıç ​​değerini bir kez ayarlayın `onMounted` ve bağlama `:value`veya geri gönderilen her tuş vuruşu `v-model` textarea'nın üzerine yazardı.

<Snippet view="code">

```javascript
&lt;script setup&gt;
import { ref, onMounted, onBeforeUnmount } from 'vue';
import MarkdownEditor from 'markdown-text-editor';

const el = ref(null);
const props = defineProps({ modelValue: { type: String, default: '' } });
const emit = defineEmits(['update:modelValue']);
let editor = null;

onMounted(() => {
    el.value.value = props.modelValue;
    editor = new MarkdownEditor(el.value, {
        onChange: value =&gt; emit('update:modelValue', value)
    });
});

onBeforeUnmount(() =&gt; editor?.destroy());
&lt;/script&gt;

&lt;template&gt;&lt;textarea ref="el"&gt;&lt;/textarea&gt;&lt;/template&gt;
```

</Snippet>

Olarak kullanılır `<MarkdownField v-model="content" />`. Sade bir biçimde atlayabilirsiniz `v-model` tamamen ve diğer çerçevelerde olduğu gibi, gönderildiğinde textarea'daki değeri okuyun.


### Sunucu tarafı oluşturma

Düzenleyicinin sunucuya aktarılması sorun yaratmaz, bu nedenle Next.js, Remix, Nuxt ve SvelteKit'e gerek yoktur `dynamic(..., { ssr: false })` etrafına sarın.

Çalışmasının nedeni yukarıdaki kuraldır: editör içeride yaratılır `useEffect`, `onMounted` veya `onMount`ve bunların hiçbiri sunucuda çalışmıyor. DOM çalışması tarayıcıda kalır.

<Snippet view="code">

```javascript
// app/page.tsx — a server component, nothing opted out of SSR
import MarkdownField from './MarkdownField';

export default function Page() {
    return (
        <form method="post">
            <MarkdownField name="content" defaultValue="# Hello" />
        </form>
    );
}
```

</Snippet>

The `<textarea>` içeriği zaten içinde olan sunucu HTML'sinde gönderilir, bu nedenle bekleyecek hiçbir şey ve ortaya çıkacak hiçbir şey yoktur. React her iki tarafta da aynı işaretlemeyi yapar ve editör hidrasyondan sonra bunu geliştirir, bu nedenle uyarılacak bir uyumsuzluk yoktur.

## Yapılandırma

Editörün davranışını ve arayüzünü tamamen özelleştirmek için `options` nesne. Bir seçeneği atlarsanız, **varsayılan** değeri kullanılır.

Editör oluşturulduğunda seçenekler bir kez okunur. Daha sonra değiştirmenin bir etkisi yoktur: ara `destroy()` ve bunun yerine yeni bir düzenleyici oluşturun.

<DocTable wrapper="overflow-x-auto w-full not-prose" table="table table-md">

| Mülkiyet | Tür | Varsayılan | Amaç |
| --- | --- | --- | --- |
| `mode` | `string` | `'plain'` | İlk görünümü ayarlar. WYSIWYG deneyimi için hibrit veya ham sözdizimi için düz kullanın. |
| `placeholder` | `string` | `'Write...'` | Editör boş olduğunda gösterilen metin. |
| `toolbar` | `array` | `[...]` | Hangi araçların hangi sırayla görüneceğini tanımlar. |
| `footer` | Yanlış| nesne | Tümü Görülebilir | Düzenleyicinin altında gösterilen durum çubuğunu kontrol eder. Ayarlayın `false` tamamen gizlemek veya bireysel istatistikleri değiştirmek için bir nesneyi geçirmek. |
| `theme` | `string` | inherited | Editör temasını (açık, koyu, snowberry, darkberry) açıkça ayarlar. Atlanırsa, editör devralır `data-theme` en yakın ata öğesinden veya `<textarea>` kanıtlıyor.  |
| `minHeight` | `number` | `200` | İçerik kısa olduğunda düzenleyicinin küçüleceği piksel cinsinden minimum yükseklik. Şununla eşleşir: `maxHeight` otomatik büyüme aralığını ayarlamak için. |
| `maxHeight` | `number` | `500` | Editörün tam ekran olmayan modda büyüyebileceği piksel cinsinden maksimum yükseklik. İçerik bu yüksekliği aştığında düzenleyicinin içinde bir kaydırma çubuğu görünür. Editör ayrıca, kullanıcıların bu sınırın ötesinde manuel olarak yeniden boyutlandırabilmeleri için bir sürükleme tutamacına sahiptir. |
| `renderer` | `function` | `marked` | Önizleme için kullanılan markdown ayrıştırıcısının yerini alır. Markdown dizesini alır ve bir HTML dizesi döndürmelidir. |

| `onChange` | `function` | `undefined` | Her içerik değişikliğinde geri arama yapılır: yazma, araç çubuğu eylemleri, geri alma/yineleme ve listenin devamı. Geçerli markdown dizesini tek bağımsız değişkeni olarak alır. |
| `locale` | `object` | `undefined` | İngilizce dizesi tarafından anahtarlanan editörün kendi arayüzü için çeviriler. Atladığınız her şey İngilizce kalır. |

</DocTable>

#### Başlık seviyeleri

The `heading` açılır menü H1 'den H6' ya kadar sunar. H1 'in çoğu CMS gövde alanı için geçerli olan içerikten ziyade sayfaya ait olduğu durumlarda, onu daraltın:

<Snippet view="code">

```javascript
new MarkdownEditor('#markdown-editor', {
    toolbar: [{ heading: { levels: [2, 3, 4] } }, 'bold', 'italic', 'preview']
});
```

</Snippet>

`Ctrl+1`, `Ctrl+2` ve `Ctrl+3` aynı listeyi takip edin, böylece bıraktığınız bir seviye klavyeden de eklenemez ve düğmenin araç ipucu yalnızca hala çalışan kısayolları listeler. Bunları yazdığınız sıralama önemli değildir, menü her zaman önce H1 'dir. 1' den 6 'ya kadar olan seviyeler bir konsol uyarısı ile göz ardı edilir ve içinde kullanılabilir hiçbir şey olmayan bir liste, boş bir menü oluşturmak yerine altısına da geri döner.

Bu, belgeyi değil, araç çubuğunu kısıtlar. Birisi hala yazabilir `# Title` ve bir başlık olarak işlenir, çünkü geçerli indirim, araç çubuğundan ziyade işleyicinin kararıdır. Kuralın geçerli olması gerekiyorsa, sunucuda uygulayın.

#### Kendi markajına ihtiyaç duyan araçlar

Bir açılır menü veya iletişim kutusu bildirimsel olarak tanımlanamaz, bu nedenle bunun yerine bir sınıf yazın. Uzatın `MarkdownEditor.Tool` set `this.button` yapıcıda ve uygulamada `applySyntax()`.

<Snippet view="code">

```javascript
class EmbedTool extends MarkdownEditor.Tool {
    constructor(editor) {
        super(editor, 'Embed video');        // tooltip, and .embed-video-btn
        this.shortcut = 'Ctrl+Shift+E';      // optional
        this.button = this.createButton('<svg>…</svg>');
    }

    applySyntax(event) {
        const dialog = MarkdownEditor.modal(event, 'fj:max-w-sm', `
            <input type="url" class="embed-url fj:me-input fj:w-full">
            <button type="button" class="embed-go fj:me-btn fj:me-btn-sm">Insert</button>
        `, 'Embed');

        dialog.querySelector('.embed-go').addEventListener('click', () => {
            const url = dialog.querySelector('.embed-url').value.trim();
            if (url) this.editor.insertText(`\n<iframe src="${url}"></iframe>\n`);
            dialog.close();
        });
    }

    destroy() {
        // Called by editor.destroy(). Release anything you registered here.
    }
}

new MarkdownEditor('#markdown-editor', { toolbar: ['bold', EmbedTool, 'preview'] });
```

</Snippet>

Ile geçiş yapılandırması `{ tool: EmbedTool, config: {...} }`, yapıcının ikinci argümanı olarak gelir. Ayar `this.button` , `null` yalnızca bazı yapılandırmalarda geçerli olan bir araç için yararlı olan hiçbir şey oluşturmaz.

İzlenecek bir şey: `Tool`'nin kurucusu çağırıyor `createButton()`, bu nedenle geçersiz kılma ihtiyaçlarınız her şeyden gelmelidir `this.editor`, sonrasında atadığınız bir alandan değil `super()`.

#### İletişim yardımcısı

`MarkdownEditor.modal` yerleşik bağlantı ve görüntü araçlarının kullandığı iletişim kutusudur, bu nedenle girdi toplayan bir aracınız kendi açılır penceresini icat etmek yerine düzenleyicinin geri kalanı gibi görünür. `<dialog>` alanlarınız için sorguladığınız ve kapattığınız, zaten açık olan öğe `dialog.close()`.

<Snippet view="code">

```javascript
// (event, size classes, body HTML, aria label)
const dialog = MarkdownEditor.modal(event, 'fj:max-w-sm', '…', 'Embed');
```

</Snippet>

Pass the `event` başvurunuzun gönderime hazır olacağına inanıyoruz. `applySyntax()` alındı. Yardımcı, tıklamanın hangi editörden geldiğini bulmak için onu okur, böylece diyalog o editörün sarmalayıcısının içine eklenir ve temasını alır. Bu düzenleyicide zaten açık olan herhangi bir iletişim kutusunun yerini alır ve kapatıldığında kendisini DOM'dan kaldırır, bu nedenle temizlenecek bir şey yoktur.

### 📊 Alt Bilgi (Durum Çubuğu)

Altbilgi düzenleyicinin altına oturur ve imlecin ** çizgisini **, ** sütunu **, belgenin ** karakter sayısını ** ve isteğe bağlı olarak ** kelime sayısını** gösterir, hepsi gerçek zamanlı olarak güncellenir. Varsayılan olarak görünürdür ve her istatistik bağımsız olarak değiştirilebilir.

<DocTable wrapper="overflow-x-auto w-full not-prose" table="table table-md">

| Temel | Tür | Varsayılan | Açıklama |
| --- | --- | --- | --- |
| `line` | `boolean` | `true` | Mevcut satır numarasını göster. |
| `col` | `boolean` | `true` | Geçerli sütun numarasını göster. |
| `chars` | `boolean` | `true` | Toplam karakter sayısını göster. |
| `words` | `boolean` | `false` | Toplam kelime sayısını göster. Varsayılan olarak kapalı: olarak ayarlayın `true` Etkinleştirmek |

</DocTable>

#### Kullanım ve örnekler

<Snippet view="code">

```javascript
// Default — line, col, and chars visible
new MarkdownEditor('#editor');

// Disable the footer entirely
new MarkdownEditor('#editor', { footer: false });

// Hide only character count
new MarkdownEditor('#editor', { footer: { chars: false } });

// Hide line and column, keep character count
new MarkdownEditor('#editor', { footer: { line: false, col: false } });

// Show only line number
new MarkdownEditor('#editor', { footer: { col: false, chars: false } });

// Enable word count alongside the defaults
new MarkdownEditor('#editor', { footer: { words: true } });

// Show word count only
new MarkdownEditor('#editor', { footer: { line: false, col: false, chars: false, words: true } });
```

</Snippet>

### Modları 🔀 Düzenleme

**MarkdownEditor **, içeriğinizi yazmak ve biçimlendirmek için iki farklı yol sunar. Geleneksel sözdizimi odaklı bir görünüm ile modern, görsel öncelikli bir deneyim arasında geçiş yapabilirsiniz.

-   `plain` (**Varsayılan **): Sözdiziminin (örneğin, `**bold**` veya `# heading`) görünür. Geliştiriciler ve İndirim uzmanları için idealdir
-   `hybrid`: Yazarken biçimlendirmeyi (Kalın, İtalik, Başlıklar) gerçek zamanlı olarak işleyen ve yine de temel Markdown yapısını koruyan WYSIWYG'den ilham alan bir deneyim.

<Snippet view="code">

```javascript
// Default initialization (Plain Mode)
new MarkdownEditor('#markdown-editor');

// Explicit Plain Mode
new MarkdownEditor('#markdown-editor', {
    mode: 'plain'
});

// Hybrid (Visual) Mode
new MarkdownEditor('#markdown-editor', {
    mode: 'hybrid'
});
```

</Snippet>

#### Hibrit ve Düz Mod Önizlemesi:

##### Hibrit modu

Siz yazarken görsel biçimlendirme gerçek zamanlı olarak oluşturulur.

<RawHtml html={"<textarea class=\"hybrid-markdown-editor mb-4\" rows=\"5\" placeholder=\"Start writing...\"># Hybrid mode markdown editor This will render visual styles immediately.</textarea>"} />

##### Düz Mod (Varsayılan)

Hafif bir deneyim için ham Markdown sözdizimine odaklanır.

<RawHtml html={"<textarea class=\"plain-markdown-editor mb-4\" rows=\"5\" placeholder=\"Start writing...\"># Plain mode markdown editor This shows the raw **syntax**.</textarea>"} />

### Temalandırma

**MarkdownEditor ** temasını çevredeki sayfadan otomatik olarak devralır: yapılandırma gerekmez. Editör şunu okur: `data-theme` başlatıldığında en yakın atadan alınır, böylece sitenizin temasıyla senkronize kalır.

#### Tema nasıl çözülür (öncelik sırası)

1.  **`theme` seçenek**: seçenekler nesnesine aktarılan açık geçersiz kılma
2.  **`data-theme` üzerinde `<textarea>`**: doğrudan öğenin üzerine ayarlanır
3.  **`data-theme` herhangi bir atada**: örn. `<html>`, `<body>`veya bir ambalaj kağıdı `<div>`

#### Mevcut temalar

`'light'` (varsayılan) `'dark'`, `'snowberry'`, `'darkberry'`

##### Seçenek 1, miras alma yeri `<html>` veya herhangi bir ata (sıfır yapılandırma)

<Snippet view="code">

```html
<html data-theme="dark">
  ...
  <textarea id="markdown-editor"></textarea>
  <script>
    new MarkdownEditor('#markdown-editor'); // picks up dark automatically
  </script>
```

</Snippet>

##### 2. Seçenek: `data-theme` doğrudan `<textarea>`

<Snippet view="code">

```html
<textarea id="markdown-editor" data-theme="dark"></textarea>
<script>
  new MarkdownEditor('#markdown-editor');
</script>
```

</Snippet>

##### 3. seçenek: açık `theme` seçenek (her şeyi geçersiz kılar)

<Snippet view="code">

```javascript
new MarkdownEditor('#markdown-editor', {
    theme: 'dark'
});
```

</Snippet>

### Arabirim dili

Editörün kendi metni, araç ipuçları, menü öğeleri, kalıcı alanlar ve düğmeler varsayılan olarak İngilizcedir. `locale` çevirmek için nesne. Anahtarlar İngilizce dizelerdir, gettext'in çalışma şeklidir, bu nedenle yalnızca değiştirmek istediklerinizi listelersiniz ve eksik olan her şey İngilizce'ye geri döner.

`locale` dizgilerin kendisini alır, dil kodunu değil. `locale: 'es'` hiçbir etkisi yoktur ve konsolda öyle diyor. Bunun yerine istediğiniz dili içe aktarın, böylece kimse kullanmadığı dilleri indirmez. Adı `labels` 2.0.0 'dan önce ve bu isim hala işe yarıyor.

<Snippet view="code">

```javascript
new MarkdownEditor('#markdown-editor', {
    locale: {
        'Bold': 'Gras',
        'Italic': 'Italique',
        'Heading': 'Titre',
        'Link': 'Lien',
        'Image link': 'Lien de l\'image',
        'URL': 'URL',
        'Alt text': 'Texte alternatif',
        'Apply': 'Appliquer',
        'Uploading...': 'Téléversement...',
    },
});
```

</Snippet>

Bu, en çok sağdan sola içerikle birlikte önemlidir. Arapça, Urduca ve Farsça kendi başlarına doğru bir şekilde düzenlenmiştir, ancak sağdan sola metin üzerinde hala "Kalın" yazan bir araç çubuğu sadece yarısı çevrilmiştir.

#### Dizgilerin tam listesi

Bunlardan 45 tane var ve paket listeyi gönderiyor, böylece aramaya gitmenize gerek yok. Anahtarlar ve değerler aynıdır, bu nedenle bir çeviriden ziyade kopyalanacak bir şablondur.

<Snippet view="code">

```javascript
import template from 'markdown-text-editor/locale/template.js';
// { "Bold": "Bold", "Match case": "Match case", "{n} words": "{n} words", ... }
```

</Snippet>

Sayımlar bir `{n}` yer tutucu, böylece çeviriniz İngilizce kelime sırasına takılıp kalmak yerine numaranın nereye gideceğine karar verir.

<Snippet view="code">

```javascript
locale: {
    '{n} words': '{n} palabras',
    '{n} chars': '{n} caracteres',
}
```

</Snippet>

#### Kendi çevirilerinizi kullanma

`locale` basit bir nesneyi alır, bu yüzden nereden geldiği size bağlıdır. Çoğu projenin zaten bir çeviri sistemi vardır ve editörü bundan beslemek, ifadelerin arayüzün geri kalanıyla tutarlı olmasını sağlar. Django'da dizeler `.po` diğer her şeyi içeren dosyalar:

<Snippet view="code">

```python
from django.utils.translation import gettext as _

def edit(request):
    return render(request, 'edit.html', {
        'mte_strings': {
            'Bold': _('Bold'),
            'Italic': _('Italic'),
            'Apply': _('Apply'),
            'Uploading...': _('Uploading...'),
        },
    })
```

</Snippet>

<Snippet view="code">

```html
{{ mte_strings|json_script:"mte-strings" }}

<script type="module">
    const strings = JSON.parse(document.getElementById('mte-strings').textContent);
    new MarkdownEditor('#markdown-editor', { locale: strings });
</script>
```

</Snippet>

I18next veya vue - i18n gibi bir istemci tarafı kataloğuyla, anahtarları `t()`:

<Snippet view="code">

```javascript
import template from 'markdown-text-editor/locale/template.js';

const strings = Object.fromEntries(
    Object.keys(template).map(key => [key, i18n.t(`editor.${key}`)])
);
```

#### Önizlemedeki numune değerleri

Verilen bir giriş `sample` bu örneği önizlemede gösterirken, metin alanı gerçek yer tutucuyu tutar. Bir girdisi olmayan girdiler yazılı olarak görünür, böylece her ikisini de karıştırabilirsiniz.


</Snippet>

#### Grouping

Bir giriş yapın `items` yerine `value` başlı bir bölüm oluşturmak için. Gruplandırılmış ve düz girişler tek bir listede karıştırılabilir.

<Snippet view="code">

```javascript
{ variables: [
    { label: 'Today', value: '{{today}}', sample: '10 September 2026' },
    { label: 'Customer', items: [
        { label: 'Name',  value: '{{customer.name}}',  sample: 'Hannes' },
        { label: 'Email', value: '{{customer.email}}', sample: 'hannes@example.com' }
    ]},
    { label: 'Invoice', items: [
        { label: 'Number', value: '{{invoice.number}}' }
    ]}
]}
```

</Snippet>

#### Bilinmesi gerekenler:

-   **Editör değişkenleri asla çözmez.** Metin ekler ve uygulamanız daha sonra, genellikle sunucu tarafında gerçek değerlerin yerini alır. `sample` yalnızca önizlemenin görüntülediklerini etkiler.
-   **Etiketler düz metin olarak gösterilir **, bu nedenle bir etiketteki işaretleme asla oluşturulmaz.
-   **Hatalı biçimlendirilmiş girişler atlanır** ve kullanılabilir hiçbir şey yapılandırılmadığında düğme hiç oluşturulmaz.

Uygulamanız zaten başka bir kütüphaneyle markdown yaptığında ve önizlemenin üretimle tam olarak eşleşmesini istediğinizde bunu kullanın.

Her iki seçenek de bir dize alan ve bir dize döndüren düz işlevlerdir, bu nedenle herhangi bir ayrıştırıcı ve herhangi bir dezenfektan çalışır.

<Snippet view="code">

```javascript
import MarkdownIt from 'markdown-it';
import taskLists from 'markdown-it-task-lists';
import MarkdownEditor from 'markdown-text-editor';

const md = new MarkdownIt({ linkify: true, breaks: true }).use(taskLists);

new MarkdownEditor('#markdown-editor', {
    renderer: markdown => md.render(markdown)
});
```

</Snippet>

DOMPurify hala çıktıda çalışır, bu nedenle hiçbir şey yapılandırmadan XSS korumasını korursunuz.

#### Özel dezenfektan

Yalnızca varsayılan, oluşturucunuzun yaydığı bir şeyi sildiğinde gereklidir. DOMPurify kaldırır `<iframe>` varsayılan olarak, bu nedenle video yerleştirmelerine açıkça izin verilmelidir. Düzenleyici ile birlikte verilen kopya dahili olduğundan DOMPurify kendi kodunuzda içe aktarılmalıdır.

<Snippet view="code">

```javascript
import DOMPurify from 'dompurify';

new MarkdownEditor('#markdown-editor', {
    renderer:  markdown => md.render(markdown),
    sanitizer: html => DOMPurify.sanitize(html, {
        ADD_TAGS: ['iframe'],
        ADD_ATTR: ['allow', 'allowfullscreen', 'frameborder']
    })
});
```

</Snippet>

Paketleyici yerine bir komut dosyası etiketi kullanarak düzenleyicinin yanına DOMPurify'ı yükleyin:

<Snippet view="code">

```html
<script src="https://cdn.jsdelivr.net/npm/dompurify"></script>
<script src="https://cdn.jsdelivr.net/npm/markdown-text-editor"></script>
```

</Snippet>

#### Bilinmesi gerekenler:

-   ** Yalnızca önizleme .** Hibrit modun canlı biçimlendirmesi ayrı bir dahili işleyici kullanır ve etkilenmez.
-   **Görev listelerinin eklenti desteğine ihtiyacı vardır.** Tıklanabilir onay kutuları aranarak bulunur `input[type="checkbox"]` çıktıda, bu nedenle indirim gerekir `markdown-it-task-lists`. Düzenleyici, görev listesi sözdizimi tespit ederse ve onay kutusu yoksa bir uyarı kaydeder.
-   **Her ikisi de senkronize olmalıdır ** ve bir dize döndürmelidir. `async` fonksiyon yazar `[object Promise]` önizlemeye girin.
-   ** Dezenfektanı değiştirmek korumanızın yerini alır.** Şunun gibi bir geçiş: `html => html` sanitizasyonu tamamen devre dışı bırakır ve yalnızca tamamen güvenilir içerik için güvenlidir.

### 🪟 Tam Ekran ve Katmanlama (z - indeksi)

Editör tam ekranda `z-index: 10000`, sabit başlıklar ve bindirmeler için çoğu kullanıcı arayüzü çerçevesi rezervinin katmanlarını temizler. Sabit bir başlık veya kenar çubuğu hala düzenleyiciyi kapsıyorsa, bu değeri yükseltin.

Şununla geçersiz kıl: `--mte-fullscreen-z-index`. Değer yalnızca tam ekranda geçerlidir ve devralınır; dolayısıyla herhangi bir ataya ayarlanması, altındaki tüm düzenleyicileri kapsar.

<Snippet view="code">

```css
/* every editor on the page */
.markdown-editor-wrapper {
    --mte-fullscreen-z-index: 20000;
}

/* one section only - the value inherits down */
#admin-panel {
    --mte-fullscreen-z-index: 20000;
}

/* a single editor, by its textarea id */
[data-editor="notes"] {
    --mte-fullscreen-z-index: 20000;
}
```

</Snippet>

### 🔒 İçerik Güvenliği Politikası

Düzenleyici hiçbir satır içi olay işleyicisi eklemez, hiçbir satır içi olay işleyicisi eklemez. `eval`ve 2.0.0'dan itibaren hayır enjekte ediyor `<style>` eleman. Sıkı bir politikaya ihtiyaç yoktur `'unsafe-inline'` her iki yönde de bunun istisnası:

<Snippet view="code">

```
Content-Security-Policy: script-src 'self'; style-src 'self'
```

</Snippet>

2.0.0'dan önce CSS, JavaScript'in içinde taşınıyordu ve yüklendiğinde enjekte ediliyordu; bu, `style-src 'unsafe-inline'` reddediyor ([#42](https://github.com/nezanuha/markdown-text-editor/issues/42)). Bir tek seferlik durum değerlendirildi ve bırakıldı: yalnızca bir tane ve statik olarak barındırılan bir siteye sahip politikalara yardımcı olur `style-src 'self'` istek başına yeni bir nonce basan sunucusu yok. Stil sayfasının bağlanması, bazı politikalar yerine her politikayı kapsar.

Editörün kontrol edemediği şeylerden biri, kullanıcılarınızın yazdığı işaretlemedir. DOMpurify tutar `style` varsayılan olarak öznitelikler, yani `<span style="color:red">` bir belge önizlemeye kadar varlığını sürdürür ve katı bir `style-src-attr` bunu rapor edecek. Bunları şu şekilde soyun: `sanitizer` sizin için önemliyse seçenek:

<Snippet view="code">

```javascript
import DOMPurify from 'dompurify';

new MarkdownEditor('#markdown-editor', {
    sanitizer: html => DOMPurify.sanitize(html, { FORBID_ATTR: ['style'] }),
});
```

</Snippet>

## İçerik API'si

**MarkdownEditor**'ün temel güçlü yönlerinden biri, temeldeki bilgiyi korumasıdır. `<textarea>` mükemmel bir şekilde senkronize edilmiştir. İster modern bir JavaScript çerçevesi ister **Django, PHP veya Laravel** gibi geleneksel bir arka uç kullanıyor olun, iş akışı basit ve yerel kalır.

### İçerik Okuma ve Yazma

#### 1\. Yerel Yol (Önerilen)

Düzenleyici standart bir metin alanını geliştirdiğinden, tanıdık DOM yöntemlerini kullanabilirsiniz. Bu, yeni bir API öğrenmeden verilerinizle etkileşim kurmanın en hızlı yoludur.

<Snippet view="code">

```javascript
// Retrieve content via ID
const markdown = document.getElementById('markdown-editor').value;

// Set content via ID (The editor UI updates automatically)
document.getElementById('markdown-editor').value = "# New Heading Content";
```

</Snippet>

#### 2\. Değişken Referans Kullanma

Textarea öğesine bir referansınız varsa onu doğrudan kullanabilirsiniz: kitaplığa özgü API gerekmez.

<Snippet view="code">

```javascript
const textarea = document.getElementById('markdown-editor');

// Retrieve content
const markdown = textarea.value;

// Set content (the editor UI reflects this immediately)
textarea.value = "## Updated via JS";
```

</Snippet>

#### 3\. Başlangıç ​​içerik sunucusu tarafının ayarlanması

Başlangıç ​​içeriğini ayarlamanın önerilen yolu doğrudan `<textarea>` HTML: Bu, her arka uç çerçevesinde (Django, Laravel, Rails, PHP, vb.) doğal olarak çalışır ve düzenleyici bunu init'te otomatik olarak işler.

<Snippet view="code">

```html
<!-- Recommended: set content server-side -->
<textarea id="markdown-editor"># Hello World</textarea>
```

</Snippet>

İçeriği çalışma zamanında okumak veya güncellemek için yerel `textarea` değer. Arama `editor.render()` önizleme ve hibrit katmanı yenilemek için bir güncellemeden sonra.

<Snippet view="code">

```javascript
const textarea = document.getElementById('markdown-editor');

// Read
const markdown = textarea.value;

// Update at runtime
textarea.value = '# New content';
editor.render();
```

</Snippet>

#### 4\. Editörü parçalamak: `destroy()`

Arama `editor.destroy()` düzenleyici DOM sarmalayıcısını kaldırmak ve orijinali geri yüklemek için `<textarea>` belgedeki konumuna. Bir görünümün bağlantısını keserken tek sayfalı uygulamalarda kullanışlıdır.

<Snippet view="code">

```javascript
const editor = new MarkdownEditor('#markdown-editor');

// Remove the editor and restore the plain textarea
editor.destroy();
```

</Snippet>

### Değişikliklere tepki verme `onChange`

Geçmek `onChange` Her içerik değişikliğinde bilgilendirilmek için geri arama. Geçerli işaretleme dizesini alır.

<Snippet view="code">

```javascript
const editor = new MarkdownEditor('#markdown-editor', {
    onChange(value) {
        console.log('Content changed:', value.length, 'characters');
    }
});
```

</Snippet>

#### Taslak otomatik kaydetme özelliği `localStorage`

Kullanmak `onChange` Her tuş vuruşunda bir taslak kaydetmek için. Düzenleyiciyi başlatmadan önce metin alanını önceden doldurarak geri yükleyin.

<Snippet view="code">

```javascript
const DRAFT_KEY = 'my-page-draft';

// Restore saved draft before init (only if textarea starts empty)
const textarea = document.getElementById('markdown-editor');
const saved = localStorage.getItem(DRAFT_KEY);
if (saved && !textarea.value) textarea.value = saved;

// Save on every change
const editor = new MarkdownEditor('#markdown-editor', {
    onChange(value) {
        localStorage.setItem(DRAFT_KEY, value);
    }
});

// Clear draft after successful form submission
document.querySelector('form').addEventListener('submit', () => {
    localStorage.removeItem(DRAFT_KEY);
});
```

</Snippet>

### Form Gönderimi

Çünkü **MarkdownEditor** doğrudan yerel üzerinde oluşturulmuştur `<textarea>`, kutudan çıktığı anda her arka uç çerçevesiyle (Django, Laravel, PHP, Ruby on Rails, vb.) uyumludur.

Burası "Önce Yerli" felsefesinin parladığı yerdir. Formu göndermeden önce verileri manuel olarak senkronize etmeniz gerekmez. Tarayıcı, düzenleyiciye tam olarak standart bir giriş alanı gibi davranır.

<Snippet view="code">

```html

  <textarea id="markdown-editor" name="content" class="h-48" rows="5">
    # Initial Content
  </textarea>

  <button type="submit">Submit to Server</button>
</form>

<script>
  // Just initialize it. That's it.
  new MarkdownEditor('#markdown-editor');
</script>
```

</Snippet>

Sadece standart bir HTML kullanın `<form>`. `name` textarea'daki özellik, sunucunuzun içeriği tanımlamak için kullanacağı özelliktir.

##### 🚀 Neden Arka Uçlar İçin Oyunun Kurallarını Değiştiriyor?

Editör yereli koruduğu için `<textarea>` davranışı, sunucunuz verileri standart bir dize olarak işler. Sıfır ekstra mantık gerekli: hayır `preventDefault()` ve kılavuz yok `FormData` yapı.

Çoğu düzenleyici (Quill, Editor.js, simpleMDE, easyMDE gibi) verileri karmaşık JSON yapılarında kaydeder. Bir geliştirici bunları kullanıyorsa, veritabanı şemasını ve oluşturma mantığını yeniden yazması gerekir.

**MarkdownEditor** ile bir geliştirici eski bir web sitesini alıp düz bir web sitesini değiştirebilir `<textarea>` editörünüzle ve **arka uç bunun değiştiğini bile bilmiyor**. Her zaman aldığı ham metni alır ancak kullanıcı 10 kat daha iyi bir deneyim yaşar.

## 🖼️ Gelişmiş Resim Yükleme

Görüntü yüklemelerini yerel olarak yönetmek: Yavaş, bellek ağırlıklı Base64 dizelerine güvenmek yerine, hem performans hem de SEO açısından önemli bir kazançtır.

### Yapıştır ve bırak

Bir ekran görüntüsünü yapıştırın veya bir görüntü dosyasını düzenleyiciye sürükleyin; araç çubuğu düğmesiyle aynı uç nokta üzerinden yüklenir. Düzenleyicinin hiçbir zaman donmuş görünmemesi için bir yer tutucu hemen görünür ve yükleme gerçekleştiğinde bunun yerini gerçek yol alır. Yükleme başarısız olursa yer tutucu, sessizce kaybolmak yerine görünür bir işaretleyiciyle değiştirilir.

Bu ihtiyaçlar `uploadUrl` aşağıda yapılandırılmıştır. Bu olmadan, bir resmin yapıştırılması hiçbir şey yapmaz ve editör, ne ekleneceğini açıklayan bir uyarıyı günlüğe kaydeder, çünkü alternatif, veritabanınızdaki bir Base64 dizesi olacaktır.

Aynı anda birkaç dosya tek tek yüklenir, böylece görüntüler geldikleri sıraya göre yerleştirilir.

### Yapılandırma Seçenekleri

Görüntü aracı şunları destekler: `fileInput` doğrudan sunucu yüklemelerini yönetecek yapılandırma.

-   `accept`: İzin verilen resim formatlarının bir dizisini tanımlayın (ör. 'webp', 'avif')
-   `uploadUrl`: Arka uç uç noktasını belirtin. `File` nesne aracılığıyla gönderilecek `POST`
-   `params`: Görüntü dosyasının yanında ek veriler (CSRF belirteçleri, kullanıcı kimlikleri veya klasör adları gibi) göndermek için isteğe bağlı nesne

### Kullanım örneği (Tam Yapılandırma)

<Snippet view="code">

```javascript
const options = {
  placeholder: 'Start writing...',
  toolbar: [
    'link',
    {
      image: {
        fileInput: {
            accept: ['webp', 'avif'], // restrict the image upload format
            uploadUrl: '/api/upload', // Your upload endpoint
            params: {
                _token: 'your_csrf_token_here', // Essential for Laravel/Django
                folder: 'blog_posts'
            }
        },
        // Supports boolean: true/false OR object: { required: true }
        altInput: { required: true }
      }
    },
    'preview'
  ],
}
const editor = new MarkdownEditor('#markdown-editor', options);
```

</Snippet>

### 📡 Sunucu Entegrasyonu

#### Talep

Editör bir mesaj gönderir `POST` olarak talep et `multipart/form-data`. Varsayılan olarak şunları içerir:

-   `image_file`: Gerçek dosya nesnesi
-   `image_alt`: Kullanıcının girdiği alternatif metin
- ...artı şu şekilde tanımlanan tüm özel veriler: `params` nesne

#### Gerekli Yanıt

Başarılı bir yüklemeyi onaylamak ve görüntüyü düzenleyiciye eklemek için sunucunuzun aşağıdaki JSON yapısını ** döndürmesi gerekir**:

<Snippet view="code">

```json
{
  "success": true,
  "image_path": "https://cdn.yourdomain.com/uploads/image.webp"
}
```

</Snippet>

**Not**: Anahtarı kullandığınızdan emin olun `image_path` yüklenen görselin URL'si için.

Ayrıca geri dönebilirsiniz `image_alt`, yalnızca kullanıcı alt alanını boş bıraktığında öneri olarak kullanılır. Kendi yazdıkları her şey her zaman kazanır, dolayısıyla dosya adından veya resim tanımadan alternatif metin türeten bir sunucu, bunu gerçek bir açıklamanın üzerine yazmadan sunabilir.

<Snippet view="code">

```json
{
  "success": true,
  "image_path": "https://cdn.yourdomain.com/uploads/image.webp",
  "image_alt": "Two people looking at a laptop"
}
```

</Snippet>

Başarısızlık durumunda geri dönüş `success: false` bir ile `error` veya `message` sicim. Bu metin kullanıcıya gösterilir, bu nedenle onu üzerinde işlem yapabilecekleri bir şey haline getirin.

### Resim Alternatif Metin Doğrulaması (`altInput`)

İçeriğinizin erişilebilir ve SEO dostu kalmasını sağlamak için **MarkdownEditor** varsayılan olarak alternatif metin doğrulamasını zorunlu kılar.

- **Varsayılan Davranış**: Eğer `altInput` tanımlanmamıştır, varsayılan olarak `{ required: true }`
- **Erişilebilirliği Zorunlu Hale Getirin**: Bir alternatif açıklama sağlanana kadar kullanıcıların resim eklemesi engellenecektir

#### 1\. Varsayılan (Yapılandırma gerekmez)

<Snippet view="code">

```javascript
// Alt text is REQUIRED by default
image: {
  fileInput: { uploadUrl: '/api/upload' }
}
```

</Snippet>

#### 2\. Kısayol (Doğrulamayı Devre Dışı Bırak)

Açıklamaları olmayan görsellere izin vermek istiyorsanız boole değerini şu şekilde ayarlamanız yeterlidir: `false`.

<Snippet view="code">

```javascript
image: {
  altInput: false // Users can now skip the alt text field
}
```

</Snippet>

#### 3\. Nesne tabanlı (Açık)

<Snippet view="code">

```javascript
image: {
    altInput: {
        required: false // Disables alt text validation — users can skip the alt field
    }
}
```

</Snippet>

### Standart Görüntü Kullanımı (Hayır `fileInput`)

Eğer `fileInput` yapılandırılmamışsa, düzenleyici varsayılan olarak basit bir URL tabanlı modeli kullanır. Kullanıcılarınız çoğunlukla harici resim barındırıcılarına bağlantı veriyorsa bu idealdir.

<Snippet view="code">

```javascript
const options = {
  toolbar: [
    'link',
    'image',
    'preview'
  ],
}
const editor = new MarkdownEditor('#markdown-editor', options);
```

</Snippet>

### 💡 Param'ları neden kullanmalıyım?

Laravel veya Django gibi çerçevelerde CSRF belirteci olmadan dosya yükleyemezsiniz. Ekleyerek `_token` -e `params` isteğiniz, sunucu tarafı denetleyicileriniz için "Sıfır Mantık" felsefesini koruyarak arka ucun güvenlik ara yazılımından sorunsuz bir şekilde geçecektir.

| `Ctrl + Shift + F`  /  `⌘ ⇧ F` | Tam ekran önizlemeyi değiştir |
| `F11` | Tam ekran önizlemeyi değiştir |
| `Escape` | Bul panelini kapat / Tam ekran önizlemeden çık |

</DocTable>

## 🔍 Bul ve Değiştir

Düzenleyicinin içinde yerleşik bir bul ve değiştir paneli mevcuttur: tarayıcı uzantısına veya ayrı bir araca gerek yoktur.

-   Basmak `Ctrl + F` (veya `⌘ F`) **Bul** panelini açmak için
-   Basmak `Ctrl + H` (veya `⌘ H`) **Bul ve Değiştir** panelini açmak için
- Arama **büyük/küçük harfe duyarlı değildir** ve canlı bir maç sayacı gösterir (ör. *3/12*)
- **▲ / ▼** düğmelerini kullanarak maçlarda gezinin veya `Enter` / `Shift + Enter`
- **Değiştir** mevcut vurgulanan eşleşmenin yerine geçer; **Tümünü Değiştir** her tekrarı aynı anda değiştirir
-   Basmak `Escape` paneli kapatmak ve odağı düzenleyiciye geri döndürmek için

Panel, düzenleyici içerik alanının sağ üst köşesinde kayar ve yazmayı kesintiye uğratmaz.

## 🔗 Yapıştırılan bir URL'den bağlantılar

Bir metin seçin, üzerine bir URL yapıştırın ve seçtiğiniz şeyin yerine geçen URL yerine bir işaretleme bağlantısı elde edersiniz.

<Snippet view="code">

```markdown
Read the docs                        <- select "the docs", paste https://example.com
Read [the docs](https://example.com) <- what you get
```

</Snippet>

Kural kasıtlı olarak katıdır: yalnızca çıplak bir `http` veya `https` Boşluk içermeyen URL bu şekilde ele alınır. URL içeren bir cümleyi yapıştırmak veya hiçbir şey seçilmeden yapıştırmak sıradan bir yapıştırma gibi davranır.
