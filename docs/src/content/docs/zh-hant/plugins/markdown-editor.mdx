Markdown 文字編輯器插件，可將本機文字區域轉換為完整的編輯套件 - 無需同步。所見即所得和純 Markdown 模式、即時預覽、尋找和替換、RTL 支援、深色模式。適用於 Django、Laravel、Rails、Node.js、PHP 和任何堆疊。

## 安裝

#### NPM（捆綁器：Vite、webpack、Rollup 等）

<Snippet view="code">

```bash
npm install markdown-text-editor
```

</Snippet>

<Snippet view="code">

```javascript
import MarkdownEditor from 'markdown-text-editor';
new MarkdownEditor('#markdown-editor');
```

</Snippet>

TypeScript 定義隨軟體包一起提供，因此選項、工具列條目和變數形狀都會被檢查並自動完成，無需額外安裝。

#### CDN：ES模組

<Snippet view="code">

```html
<script type="module">
  import MarkdownEditor from 'https://cdn.jsdelivr.net/npm/markdown-text-editor/+esm';
  new MarkdownEditor('#markdown-editor');
</script>
```

</Snippet>

#### CDN：全域腳本標籤（IIFE）

無需導入 - MarkdownEditor 可自動作為全域變數使用。

<Snippet view="code">

```html
<form action="/api/save" method="POST">
  <textarea id="markdown-editor" name="content"># Hello World</textarea>
  <button type="submit">Save Content</button>
</form>

<script src="https://cdn.jsdelivr.net/npm/markdown-text-editor"></script>
<script>
  new MarkdownEditor('#markdown-editor');
</script>
```

</Snippet>

## 理念：“本土第一”

大多數編輯器都打破了標準的網路工作流程。 **MarkdownEditor** 擁抱它。因為它直接位於 `<textarea>`，您不需要學習處理資料的新方法。

- **無需資料綁定：** 適用於 `<form method="POST">` 開箱即用
- **標準訪問：** 使用 `document.getElementById('editor').value` 就像普通輸入一樣。
- **與後端無關：** 可與任何後端（Python、Node.js、PHP 等）一起使用，就像普通表單欄位一樣

## MarkdownEditor 與 EasyMDE / SimpleMDE

大多數 JavaScript Markdown 編輯器 — EasyMDE、SimpleMDE、基於 CodeMirror 的編輯器 — **隱藏您的 `<textarea>`** 並編輯副本，提交表單時寫回內容。這一直有效，直到其他東西需要該值： `required` 瀏覽器無法聚焦的欄位會完全阻止提交，並且 `.value` 或者 `FormData` 在提交之前讀取會傳回一個空字串，這會破壞 htmx、Turbo、自動儲存和未儲存變更防護。 **MarkdownEditor 是不同的** — 它對您已有的文字區域進行樣式設置，並將其保留為您輸入的字段，因此該值在任何時候都是正確的。

<DocTable wrapper="overflow-x-auto w-full not-prose" table="table table-md">

| 特徵 | Markdown編輯器 | EasyMDE / SimpleMDE |
| --- | --- | --- |
| 保留本機文字區域 | ✅ | ❌ 隱藏，編輯為副本 |
| 與 `required` 領域 | ✅ | ❌ 瀏覽器阻止提交 |
| `.value` 提交前更正 | ✅ | ❌ 表單提交之前為空 |
| 連載於 `FormData`, htmx, 渦輪增壓 | ✅ | ❌ 需要編輯器自己的API |
| 所見即所得混合模式 | ✅ | ❌ |
| 內建尋找和替換 | ✅ | ❌ |
| RTL 支持 | ✅ 內置 | 透過 CodeMirror 的 `direction` 選項 |
| 內嵌事件處理程序 (CSP) | ✅ 無 | 一些 |
| 深色模式/主題 | ✅ | 有限的 |
| 捆綁包大小，gzip 壓縮 | 51 KB | 107 KB（JS + CSS） |

</DocTable>

## 框架整合

因為 **MarkdownEditor** 保留了原生 `<textarea>`，它與每個後端框架集成，無需任何額外程式碼。您的伺服器接收 Markdown 內容，就像從任何標準表單欄位接收一樣。對於 React 和 Vue，它需要幾行，在本節末尾介紹。

### 薑戈

添加一個 `class` 到您的文字區域小部件並初始化編輯器 - `request.POST['content']` 無需額外步驟即可工作。

<Snippet view="code">

```python
# forms.py
class PostForm(forms.ModelForm):
    class Meta:
        model = Post
        fields = ['content']
        widgets = {
            'content': forms.Textarea(attrs={'class': 'markdown-editor'}),
        }
```

</Snippet>

<Snippet view="code">

```javascript
new MarkdownEditor('.markdown-editor');
// request.POST['content'] contains the markdown on submit
```

</Snippet>

### 反應

在效果中建立編輯器並在卸載時銷毀它。使用 `defaultValue` 而不是 `value`：編輯器直接寫入文字區域，因此受控綁定將覆蓋使用者輸入的內容。

<Snippet view="code">

```javascript
import { useEffect, useRef } from 'react';
import MarkdownEditor from 'markdown-text-editor';

function MarkdownField({ name, defaultValue = '', onChange }) {
    const ref = useRef(null);

    useEffect(() => {
        const editor = new MarkdownEditor(ref.current, { onChange });
        return () => editor.destroy();
    }, []);

    return &lt;textarea ref={ref} name={name} defaultValue={defaultValue} /&gt;;
}
```

</Snippet>

返回 `editor.destroy()` from theeffect 還涵蓋了 StrictMode，它在開發過程中運行兩次效果，否則會在一個文字區域上留下兩個編輯器。空依賴數組是故意的：創建編輯器時會讀取一次選項，因此重新運行效果會拆除它並在每次更改時重建它。

### 維埃

同樣的想法。設定一次初始值 `onMounted` 並且不綁定 `:value`，或透過發送回的每個擊鍵 `v-model` 會覆蓋文字區域。

<Snippet view="code">

```javascript
&lt;script setup&gt;
import { ref, onMounted, onBeforeUnmount } from 'vue';
import MarkdownEditor from 'markdown-text-editor';

const el = ref(null);
const props = defineProps({ modelValue: { type: String, default: '' } });
const emit = defineEmits(['update:modelValue']);
let editor = null;

onMounted(() => {
    el.value.value = props.modelValue;
    editor = new MarkdownEditor(el.value, {
        onChange: value =&gt; emit('update:modelValue', value)
    });
});

onBeforeUnmount(() =&gt; editor?.destroy());
&lt;/script&gt;

&lt;template&gt;&lt;textarea ref="el"&gt;&lt;/textarea&gt;&lt;/template&gt;
```

</Snippet>

用作 `<MarkdownField v-model="content" />`。在簡單的形式中，您可以跳過 `v-model` 與任何其他框架一樣，完全並在提交時從文字區域讀取值。

## 配置

您可以透過傳遞一個來完全自訂編輯器的行為和介面 `options` 目的。如果省略選項，則使用 **預設** 值。

建置編輯器時，選項將被讀取一次。之後更改它們沒有任何效果 - 調用 `destroy()` 並建立一個新的編輯器。

<DocTable wrapper="overflow-x-auto w-full not-prose" table="table table-md">

| 財產 | 類型 | 預設 | 目的 |
| --- | --- | --- | --- |
| `mode` | `string` | `'plain'` | 設定初始視圖。使用混合以獲得所見即所得的體驗，或使用普通的原始語法。 |
| `placeholder` | `string` | `'Write...'` | 編輯器為空時顯示的文字。 |
| `toolbar` | `array` | `[...]` | 定義顯示哪些工具以及顯示順序。 |
| `footer` | `假\| 對象` | 全部可見 | 控制編輯器下方顯示的狀態列。設定為 `false` 完全隱藏它，或傳遞一個物件來切換單一統計資料。 |
| `theme` | `string` | inherited | 明確設定編輯器主題（淺色、深色、雪莓、黑莓）。如果省略，編輯器繼承 `data-theme` 從最近的祖先元素或 `<textarea>` 本身。 |
| `minHeight` | `number` | `200` | 當內容較短時，編輯器將縮小到的最小高度（以像素為單位）。配對 `maxHeight` 設定自動增長範圍。 |
| `maxHeight` | `number` | `500` | 編輯器在非全螢幕模式下可以增長到的最大高度（以像素為單位）。一旦內容超過此高度，編輯器內就會出現捲軸。該編輯器還有一個拖曳手柄，因此使用者可以手動將其大小調整到超出此限制。 |
| `renderer` | `function` | `marked` | 替換用於預覽的 Markdown 解析器。接收 markdown 字串並且必須傳回 HTML 字串。 |
| `sanitizer` | `function` | `DOMPurify` | 取代 HTML 清理程式。接收渲染的 HTML，必須傳回安全的 HTML 來顯示。 |
| `onChange` | `function` | `undefined` | 每次內容變更時都會觸發回調 - 鍵入、工具列操作、撤銷/重做和清單延續。接收目前的 markdown 字串作為其唯一的參數。 |

</DocTable>

#### 使用範例

<Snippet view="code">

```javascript
// Default — line, col, and chars visible
new MarkdownEditor('#editor');

// Disable the footer entirely
new MarkdownEditor('#editor', { footer: false });

// Hide only character count
new MarkdownEditor('#editor', { footer: { chars: false } });

// Hide line and column, keep character count
new MarkdownEditor('#editor', { footer: { line: false, col: false } });

// Show only line number
new MarkdownEditor('#editor', { footer: { col: false, chars: false } });

// Enable word count alongside the defaults
new MarkdownEditor('#editor', { footer: { words: true } });

// Show word count only
new MarkdownEditor('#editor', { footer: { line: false, col: false, chars: false, words: true } });
```

</Snippet>

### 🔀 編輯模式

**MarkdownEditor** 提供兩種不同的方式來撰寫和格式化內容。您可以在傳統的以語法為中心的視圖或現代的視覺優先體驗之間切換。

-   `plain` （**預設**）：一個乾淨、高效能的 Markdown 環境，其中語法（例如 `**bold**` 或者 `# heading`) 可見。開發人員和 Markdown 純粹主義者的理想選擇
-   `hybrid`：所見即所得的體驗，可在您鍵入時即時呈現格式（粗體、斜體、標題），同時仍保持底層 Markdown 結構。

<Snippet view="code">

```javascript
// Default initialization (Plain Mode)
new MarkdownEditor('#markdown-editor');

// Explicit Plain Mode
new MarkdownEditor('#markdown-editor', {
    mode: 'plain'
});

// Hybrid (Visual) Mode
new MarkdownEditor('#markdown-editor', {
    mode: 'hybrid'
});
```

</Snippet>

### 🌙 主題化

**MarkdownEditor** 自動從周圍頁面繼承其主題 - 無需配置。編輯讀到 `data-theme` 從初始化時最近的祖先開始，因此它與您網站的開箱即用主題保持同步。

#### 主題如何解決（優先順序）

1.  **`theme` option** — 在選項物件中傳遞的明確覆蓋
2.  **`data-theme` 於 `<textarea>`** — 直接在元素上設置
3.  **`data-theme` 任何祖先**——例如 `<html>`, `<body>`，或包裝器 `<div>`

#### 可用主題

`'light'` (預設), `'dark'`, `'snowberry'`, `'darkberry'`

##### 選項 1 — 繼承自 `<html>` 或任何祖先（零配置）

<Snippet view="code">

```html
<html data-theme="dark">
  ...
  <textarea id="markdown-editor"></textarea>
  <script>
    new MarkdownEditor('#markdown-editor'); // picks up dark automatically
  </script>
```

</Snippet>

##### 選項 2 — 設定 `data-theme` 直接在 `<textarea>`

<Snippet view="code">

```html
<textarea id="markdown-editor" data-theme="dark"></textarea>
<script>
  new MarkdownEditor('#markdown-editor');
</script>
```

</Snippet>

##### 選項 3 — 顯式 `theme` 選項（覆蓋所有內容）

<Snippet view="code">

```javascript
new MarkdownEditor('#markdown-editor', {
    theme: 'dark'
});
```

</Snippet>

### 🏷 變數

新增用於插入佔位符的工具列下拉清單。當編寫文件的人不是定義佔位符語法的開發人員時很有用，例如電子郵件、發票或合約範本：他們選擇一個可讀的名稱，並為其插入正確的語法。

<Snippet view="code">

```javascript
new MarkdownEditor('#markdown-editor', {
    toolbar: ['bold', 'italic', 'link',
        { variables: [
            { label: 'Customer Name', value: '{{customer.name}}' },
            { label: 'Invoice No',    value: '{{invoice.number}}' }
        ]},
        'preview'
    ]
});
```

</Snippet>

該工具是內聯配置的 `toolbar` 數組，因此它在其他按鈕中的位置取決於您。該按鈕列出了標籤，單擊其中一個即可插入其標籤 `value` 在遊標處，替換任何選擇。如果清單為空，則不會呈現任何內容。

#### 預覽中的範例值

給定的條目 `sample` 在預覽中顯示該範例，而文字區域保留真實的佔位符。沒有其中之一的條目將以書面形式顯示，因此您可以將兩者混合使用。

<Snippet view="code">

```javascript
{ variables: [
    { label: 'Customer Name', value: '{{customer.name}}', sample: 'Hannes' },
    { label: 'Invoice No',    value: '{{invoice.number}}' }
]}

// textarea : Hi {{customer.name}}, invoice {{invoice.number}}
// preview  : Hi Hannes, invoice {{invoice.number}}
```

</Snippet>

#### 分組

給出一個條目 `items` 而不是 `value` 渲染一個有標題的部分。分組條目和平面條目可以混合在一個清單中。

<Snippet view="code">

```javascript
{ variables: [
    { label: 'Today', value: '{{today}}', sample: '10 September 2026' },
    { label: 'Customer', items: [
        { label: 'Name',  value: '{{customer.name}}',  sample: 'Hannes' },
        { label: 'Email', value: '{{customer.email}}', sample: 'hannes@example.com' }
    ]},
    { label: 'Invoice', items: [
        { label: 'Number', value: '{{invoice.number}}' }
    ]}
]}
```

</Snippet>

#### 要知道的事情

- **編輯器從不解析變數。 ** 它插入文本，然後您的應用程式通常在伺服器端替換實際值。 `sample` 僅影響預覽顯示的內容。
- **標籤顯示為純文字**，因此標籤中的標記永遠不會呈現。
- **格式錯誤的條目將被跳過**而不是拋出，並且當未配置任何可用的內容時，根本不會呈現按鈕。

### 🖋 自訂渲染器

預覽呈現為 [標記的](https://marked.js.org) 並用消毒 [DOM純化](https://github.com/cure53/DOMPurify)。兩者都可以更換。當您的應用程式已經使用另一個程式庫呈現 Markdown 並且您希望預覽與生產完全匹配時，請使用此選項。

這兩個選項都是普通函數，它們接受一個字串並傳回一個字串，因此任何解析器和任何清理程式都可以工作。

<Snippet view="code">

```javascript
import MarkdownIt from 'markdown-it';
import taskLists from 'markdown-it-task-lists';
import MarkdownEditor from 'markdown-text-editor';

const md = new MarkdownIt({ linkify: true, breaks: true }).use(taskLists);

new MarkdownEditor('#markdown-editor', {
    renderer: markdown => md.render(markdown)
});
```

</Snippet>

DOMPurify 仍然在輸出上運行，因此您無需配置任何內容即可保持 XSS 保護。

#### 客製化消毒液

僅當預設刪除渲染器發出的內容時才需要。 DOMPurify 刪除 `<iframe>` 預設情況下，因此視訊嵌入需要明確允許。 DOMPurify 必須在您自己的程式碼中匯入，因為與編輯器捆綁的副本是內部的。

<Snippet view="code">

```javascript
import DOMPurify from 'dompurify';

new MarkdownEditor('#markdown-editor', {
    renderer:  markdown => md.render(markdown),
    sanitizer: html => DOMPurify.sanitize(html, {
        ADD_TAGS: ['iframe'],
        ADD_ATTR: ['allow', 'allowfullscreen', 'frameborder']
    })
});
```

</Snippet>

使用腳本標籤而不是捆綁器，將 DOMPurify 與編輯器一起載入：

<Snippet view="code">

```html
<script src="https://cdn.jsdelivr.net/npm/dompurify"></script>
<script src="https://cdn.jsdelivr.net/npm/markdown-text-editor"></script>
```

</Snippet>

#### 要知道的事情

- **僅限預覽。 ** 混合模式的即時格式使用單獨的內部渲染器，且不受影響。
- **任務清單需要插件支援。 **可透過尋找找到可點選的複選框 `input[type="checkbox"]` 在輸出中，所以 markdown-it 需要 `markdown-it-task-lists`。如果編輯器偵測到任務清單語法且沒有複選框，則會記錄警告。
- **兩者必須同步**並傳回字串。一個 `async` 函數寫入 `[object Promise]` 進入預覽。
- **更換消毒劑取代了您的保護。 ** 傳遞，例如 `html => html` 完全禁用清理，並且僅對完全信任的內容是安全的。

### 🪟 全螢幕和分層（z-index）

在全螢幕模式下，編輯器使用 `z-index: 10000`，這會清除大多數 UI 框架為固定標題和覆蓋層保留的層。如果固定標題或側邊欄仍然覆蓋編輯器，請提高此值。

覆蓋它 `--mte-fullscreen-z-index`。該值僅適用於全屏，並且會繼承，因此在任何祖先上設置它都會覆蓋其下面的每個編輯器。

<Snippet view="code">

```css
/* every editor on the page */
.markdown-editor-wrapper {

}

/* one section only - the value inherits down */
#admin-panel {
    --mte-fullscreen-z-index: 20000;
}

/* a single editor, by its textarea id */
[data-editor="notes"] {
    --mte-fullscreen-z-index: 20000;
}
```

</Snippet>

## 內容API

**MarkdownEditor** 的核心優勢之一是它保留了底層 `<textarea>` 完美同步。無論您使用現代 JavaScript 框架還是傳統後端（例如 **Django、PHP 或 Laravel**），工作流程都保持簡單且原生。

### 閱讀和寫作內容

#### 1\.本土方式（推薦）

由於編輯器增強了標準文字區域，因此您可以使用熟悉的 DOM 方法。這是無需學習新 API 即可與資料互動的最快方式。

<Snippet view="code">

```javascript
// Retrieve content via ID
const markdown = document.getElementById('markdown-editor').value;

// Set content via ID (The editor UI updates automatically)
document.getElementById('markdown-editor').value = "# New Heading Content";
```

</Snippet>

#### 2\.使用變數引用

如果您有對 textarea 元素的引用，則可以直接使用它 - 不需要特定於庫的 API。

<Snippet view="code">

```javascript
const textarea = document.getElementById('markdown-editor');

// Retrieve content
const markdown = textarea.value;

// Set content (the editor UI reflects this immediately)
textarea.value = "## Updated via JS";
```

</Snippet>

#### 3\.設定初始內容伺服器端

設定初始內容的建議方法是直接在 `<textarea>` HTML——這可以自然地適用於每個後端框架（Django、Laravel、Rails、PHP 等），並且編輯器會在 init 上自動呈現它。

<Snippet view="code">

```html
<!-- Recommended: set content server-side -->
<textarea id="markdown-editor"># Hello World</textarea>
```

</Snippet>

若要在執行時間讀取或更新內容，請使用本機 `textarea` 價值。稱呼 `editor.render()` 更新後刷新預覽和混合層。

<Snippet view="code">

```javascript
const textarea = document.getElementById('markdown-editor');

// Read
const markdown = textarea.value;

// Update at runtime
textarea.value = '# New content';
editor.render();
```

</Snippet>

#### 4\.拆掉編輯器—— `destroy()`

稱呼 `editor.destroy()` 刪除編輯器 DOM 包裝並恢復原始狀態 `<textarea>` 到其在文檔中的位置。在單頁應用程式中卸載視圖時很有用。

<Snippet view="code">

```javascript
const editor = new MarkdownEditor('#markdown-editor');

// Remove the editor and restore the plain textarea
editor.destroy();
```

</Snippet>

### 對變化做出反應 `onChange`

透過一個 `onChange` 每次內容變更時都會收到回呼通知。接收目前的 Markdown 字串。

<Snippet view="code">

```javascript
const editor = new MarkdownEditor('#markdown-editor', {
    onChange(value) {
        console.log('Content changed:', value.length, 'characters');
    }
});
```

</Snippet>

#### 草稿自動儲存 `localStorage`

使用 `onChange` 每次擊鍵時儲存草稿。在初始化編輯器之前透過預先填充文字區域來恢復它。

<Snippet view="code">

```javascript
const DRAFT_KEY = 'my-page-draft';

// Restore saved draft before init (only if textarea starts empty)
const textarea = document.getElementById('markdown-editor');
const saved = localStorage.getItem(DRAFT_KEY);
if (saved && !textarea.value) textarea.value = saved;

// Save on every change
const editor = new MarkdownEditor('#markdown-editor', {
    onChange(value) {
        localStorage.setItem(DRAFT_KEY, value);
    }
});

// Clear draft after successful form submission
document.querySelector('form').addEventListener('submit', () => {
    localStorage.removeItem(DRAFT_KEY);
});
```

</Snippet>

### 表格提交

因為 **MarkdownEditor** 是直接建構在原生之上的 `<textarea>`，它開箱即用，與每個後端框架（Django、Laravel、PHP、Ruby on Rails 等）相容。

這就是「本地優先」理念的閃光點。您無需在提交表單之前手動同步資料。瀏覽器將編輯器視為標準輸入欄位。

<Snippet view="code">

```html
<form method="POST" action="/api/submit">
  <textarea id="markdown-editor" name="content" class="h-48" rows="5">
    # Initial Content
  </textarea>

  <button type="submit">Submit to Server</button>
</form>

<script>
  // Just initialize it. That's it.
  new MarkdownEditor('#markdown-editor');
</script>
```

</Snippet>

<RawHtml html={"<p class=\"text-sm\"><strong>筆記：</strong> MarkdownEditor 外掛程式必須初始化</p>"} />

只需使用標準 HTML `<form>`。這 `name` 文字區域上的屬性是您的伺服器將用來識別內容的屬性。

##### 🚀 為什麼它會改變後端的遊戲規則

由於編輯器保留了原生 `<textarea>` 行為，您的伺服器將資料作為標準字串處理。所需的額外邏輯為零——不需要 `preventDefault()` 並且沒有說明書 `FormData` 建造。

##### 💡 為什麼這是一個「殺手級功能」：

大多數編輯器（如 Quill、Editor.js、simpleMDE、easyMDE）以複雜的 JSON 結構保存資料。如果開發人員使用這些，他們必須重寫他們的資料庫模式和渲染邏輯。

使用 **MarkdownEditor**，開發人員可以使用舊網站，替換普通網站 `<textarea>` 與您的編輯器一起使用，**後端甚至不知道它發生了變化**。它只是收到與往常相同的原始文本，但用戶獲得了 10 倍更好的體驗。

## 🖼️ 高級圖片上傳

本地處理圖像上傳（而不是依賴緩慢且佔用大量記憶體的 Base64 字串）對於效能和 SEO 來說都是一個重大勝利。

### 配置選項

影像工具支援 `fileInput` 配置來處理直接伺服器上傳。

-   `accept`：定義允許的圖像格式陣列（例如“webp”、“avif”）
-   `uploadUrl`：指定後端端點 `File` 對象將透過發送 `POST`
-   `params`：可選對象，用於與映像檔一起傳送附加資料（例如 CSRF 令牌、使用者 ID 或資料夾名稱）

### 使用範例（完整配置）

<Snippet view="code">

```javascript
const options = {
  placeholder: 'Start writing...',
  toolbar: [
    'link',
    {
      image: {
        fileInput: {
            accept: ['webp', 'avif'], // restrict the image upload format
            uploadUrl: '/api/upload', // Your upload endpoint
            params: {
                _token: 'your_csrf_token_here', // Essential for Laravel/Django
                folder: 'blog_posts'
            }
        },
        // Supports boolean: true/false OR object: { required: true }
        altInput: { required: true }
      }
    },
    'preview'
  ],
}
const editor = new MarkdownEditor('#markdown-editor', options);
```

</Snippet>

### 📡 伺服器集成

#### 請求

編輯發來一條 `POST` 請求為 `multipart/form-data`。預設情況下，它包括：

-   `image_file`: 實際的文件對象
-   `image_alt`：使用者輸入的替代文本
- ...加上中定義的任何自訂數據 `params` 目的

#### 所需的回應

若要確認上傳成功並將圖像插入編輯器，您的伺服器**必須**傳回以下 JSON 結構：

<Snippet view="code">

```json
{
  "success": true,
  "image_path": "https://cdn.yourdomain.com/uploads/image.webp"
}
```

</Snippet>

**注意**：確保您使用密鑰 `image_path` 為上傳圖像的 URL。

### 圖像替代文字驗證（`altInput`)

為了確保您的內容保持可訪問性和 SEO 友善性，**MarkdownEditor** 預設強制執行替代文字驗證。

- **預設行為**：如果 `altInput` 沒有定義，預設為 `{ required: true }`
- **強制可訪問性**：在提供替代說明之前，將阻止使用者插入圖像

#### 1\.預設（無需配置）

<Snippet view="code">

```javascript
// Alt text is REQUIRED by default
image: {
  fileInput: { uploadUrl: '/api/upload' }
}
```

</Snippet>

#### 2\.速記（禁用驗證）

如果您想允許沒有描述的圖像，只需將布林值設為 `false`.

<Snippet view="code">

```javascript
image: {
  altInput: false // Users can now skip the alt text field
}
```

</Snippet>

#### 3\.基於物件（顯式）

<Snippet view="code">

```javascript
image: {
    altInput: {
        required: false // Disables alt text validation — users can skip the alt field
    }
}
```

</Snippet>

### 標準影像使用（否 `fileInput`)

如果 `fileInput` 未配置時，編輯器預設為簡單的基於 URL 的模式。如果您的用戶主要連結到外部圖像主機，那麼這是理想的選擇。

<Snippet view="code">

```javascript
const options = {
  toolbar: [
    'link',
    'image',
    'preview'
  ],
}
const editor = new MarkdownEditor('#markdown-editor', options);
```

</Snippet>

### 💡 為什麼要使用參數？

在 Laravel 或 Django 等框架中，如果沒有 CSRF 令牌，則無法上傳檔案。透過添加 `_token` 到 `params` 對象，您的請求將無縫地通過後端的安全中間件，維護伺服器端控制器的「零邏輯」概念。

## 🔍 尋找和替換

編輯器內提供內建尋找和取代面板 - 無需瀏覽器擴充功能或單獨的工具。

- 按 `Ctrl + F` （或者 `⌘ F`) 開啟 **尋找** 面板
- 按 `Ctrl + H` （或者 `⌘ H`) 開啟 **尋找並取代** 面板
- 搜尋**不區分大小寫**並顯示即時比賽計數器（例如 *3 of 12*）
- 使用 **▲ / ▼** 按鈕導覽匹配或 `Enter` / `Shift + Enter`
- **替換** 取代目前反白顯示的符合項目； **全部替換** 一次取代所有出現的內容
- 按 `Escape` 關閉面板並將焦點返回編輯器

此面板浮動在編輯器內容區域的右上角，不會中斷寫入。
