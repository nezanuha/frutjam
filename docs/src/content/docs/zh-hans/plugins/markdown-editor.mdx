一个 Markdown 编辑器，可以增强您的文本区域而不是替换它，因此表单提交、验证和必填字段可以继续工作。所见即所得和纯 Markdown 模式、实时预览、查找和替换、RTL 支持、深色模式。可与 Django、Laravel、Rails、Node.js、PHP 和任何堆栈独立工作。

**不需要 Frutjam 和 Tailwind。** 样式是捆绑的，因此编辑器可以放入任何项目中。

## 安装

#### NPM（捆绑器：Vite、webpack、Rollup 等）

<Snippet view="code">

```bash
npm install markdown-text-editor
```

</Snippet>

<Snippet view="code">

```javascript
import MarkdownEditor from 'markdown-text-editor';
new MarkdownEditor('#markdown-editor');
```

</Snippet>

TypeScript 定义随软件包一起提供，因此选项、工具栏条目和变量形状都会被检查并自动完成，无需额外安装。

这些类型也是可导入的，只要您的选项不是在调用站点内联编写的，这一点就很重要。 TypeScript 仅检查直接传递的对象文字上的未知键，因此保存在其自己的变量中的配置会默默忽略拼写错误的键。对其进行注释会将检查放回原处。

<Snippet view="code">

```typescript
import MarkdownEditor, { type MarkdownEditorOptions, type ToolbarEntry } from 'markdown-text-editor';

// Without the annotation this compiles, the editor renders with the default
// toolbar, and nothing tells you why.
const config: MarkdownEditorOptions = {
    placeholder: 'Write...',
    toolbr: ['bold', 'preview'],   // Error: did you mean to write 'toolbar'?
};

// Building a toolbar conditionally
const toolbar: ToolbarEntry[] = ['bold', 'italic'];
if (canUpload) toolbar.push({ image: { fileInput: { uploadUrl: '/api/upload' } } });
toolbar.push('preview');
```

</Snippet>

这同样适用于包装组件，其中 `MarkdownEditorOptions` 是你转发的而不是 `any`，所以无论谁使用你的包装器都会进行检查。

<Snippet view="code">

```typescript
interface EditorProps {
    value: string;
    options?: MarkdownEditorOptions;
}
```

</Snippet>

## 理念：“本土第一”

大多数编辑器都打破了标准的网络工作流程。 **MarkdownEditor** 拥抱它。因为它直接位于 `<textarea>`，您不需要学习处理数据的新方法。

- **无需数据绑定：** 适用于 `<form method="POST">` 开箱即用
- **标准访问：** 使用 `document.getElementById('editor').value` 就像普通输入一样。
- **与后端无关：** 可与任何后端（Python、Node.js、PHP 等）一起使用，就像普通表单字段一样

## MarkdownEditor 与 EasyMDE / SimpleMDE

大多数 JavaScript Markdown 编辑器（EasyMDE、SimpleMDE、基于 CodeMirror 的编辑器）**隐藏您的 `<textarea>`** 并编辑副本，在提交表单时写回内容。这一直有效，直到其他东西需要该值为止： `required` 浏览器无法聚焦的字段会完全阻止提交，并且 `.value` 或者 `FormData` 在提交之前读取会返回一个空字符串，这会破坏 htmx、Turbo、自动保存和未保存更改防护。 **MarkdownEditor 是不同的。** 它对您已有的文本区域进行样式设置，并将其保留为您输入的字段，因此该值在任何时候都是正确的。

<DocTable wrapper="overflow-x-auto w-full not-prose" table="table table-md">

| 特征 | Markdown编辑器 | EasyMDE / SimpleMDE |
| --- | --- | --- |
| 保留本机文本区域 | ✅ | ❌ 隐藏，编辑为副本 |
| 与 `required` 领域 | ✅ | ❌ 浏览器阻止提交 |
| `.value` 提交前更正 | ✅ | ❌ 表单提交之前为空 |
| 连载于 `FormData`, htmx, 涡轮增压 | ✅ | ❌ 需要编辑器自己的API |
| 所见即所得混合模式 | ✅ | ❌ |
| 内置查找和替换 | ✅ | ❌ |
| RTL 支持 | ✅ 内置 | 通过 CodeMirror 的 `direction` 选项 |
| 内联事件处理程序 (CSP) | ✅ 无 | 一些 |
| 深色模式/主题 | ✅ | 有限的 |
| 捆绑包大小，gzip 压缩 | 53 KB | 107 KB（JS + CSS） |

</DocTable>

## 框架整合

因为 **MarkdownEditor** 保留了原生 `<textarea>`，它与每个后端框架集成，无需任何额外代码。您的服务器接收 Markdown 内容，就像从任何标准表单字段接收一样。对于 React 和 Vue，它需要几行，在本节末尾介绍。

### 姜戈

添加一个 `class` 到您的文本区域小部件并初始化编辑器： `request.POST['content']` 无需额外步骤即可工作。

<Snippet view="code">

```python
# forms.py
class PostForm(forms.ModelForm):
    class Meta:
        model = Post
        fields = ['content']
        widgets = {
            'content': forms.Textarea(attrs={'class': 'markdown-editor'}),
        }
```

</Snippet>

<Snippet view="code">

```javascript
new MarkdownEditor('.markdown-editor');
// request.POST['content'] contains the markdown on submit
```

</Snippet>

### 反应

在效果中创建编辑器并在卸载时销毁它。使用 `defaultValue` 而不是 `value`：编辑器直接写入文本区域，因此受控绑定将覆盖用户键入的内容。

<Snippet view="code">

```javascript
import { useEffect, useRef } from 'react';
import MarkdownEditor from 'markdown-text-editor';

function MarkdownField({ name, defaultValue = '', onChange }) {
    const ref = useRef(null);

    useEffect(() => {
        const editor = new MarkdownEditor(ref.current, { onChange });
        return () => editor.destroy();
    }, []);

    return &lt;textarea ref={ref} name={name} defaultValue={defaultValue} /&gt;;
}
```

</Snippet>

返回 `editor.destroy()` from theeffect 还涵盖了 StrictMode，它在开发过程中运行两次效果，否则会在一个文本区域上留下两个编辑器。空依赖数组是故意的：创建编辑器时会读取一次选项，因此重新运行效果会拆除它并在每次更改时重建它。

### 维埃

同样的想法。设置一次初始值 `onMounted` 并且不绑定 `:value`，或通过发送回的每个击键 `v-model` 会覆盖文本区域。

<Snippet view="code">

```javascript
&lt;script setup&gt;
import { ref, onMounted, onBeforeUnmount } from 'vue';
import MarkdownEditor from 'markdown-text-editor';

const el = ref(null);
const props = defineProps({ modelValue: { type: String, default: '' } });
const emit = defineEmits(['update:modelValue']);
let editor = null;

onMounted(() => {
    el.value.value = props.modelValue;
    editor = new MarkdownEditor(el.value, {
        onChange: value =&gt; emit('update:modelValue', value)
    });
});

onBeforeUnmount(() =&gt; editor?.destroy());
&lt;/script&gt;

&lt;template&gt;&lt;textarea ref="el"&gt;&lt;/textarea&gt;&lt;/template&gt;
```

</Snippet>

用作 `<MarkdownField v-model="content" />`。在简单的形式中，您可以跳过 `v-model` 与任何其他框架一样，完全并在提交时从文本区域读取值。

## 配置

您可以通过传递一个来完全自定义编辑器的行为和界面 `options` 目的。如果省略选项，则使用 **默认** 值。

构建编辑器时，选项将被读取一次。之后更改它们没有任何效果：调用 `destroy()` 并创建一个新的编辑器。

<DocTable wrapper="overflow-x-auto w-full not-prose" table="table table-md">

| 财产 | 类型 | 默认 | 目的 |
| --- | --- | --- | --- |
| `mode` | `string` | `'plain'` | 设置初始视图。使用混合以获得所见即所得的体验，或使用普通的原始语法。 |
| `placeholder` | `string` | `'Write...'` | 编辑器为空时显示的文本。 |
| `toolbar` | `array` | `[...]` | 定义显示哪些工具以及显示顺序。 |
| `footer` | `假\| 对象` | 全部可见 | 控制编辑器下方显示的状态栏。设置为 `false` 完全隐藏它，或者传递一个对象来切换单个统计数据。 |
| `theme` | `string` | inherited | 显式设置编辑器主题（浅色、深色、雪莓、黑莓）。如果省略，编辑器继承 `data-theme` 从最近的祖先元素或 `<textarea>` 本身。 |
| `minHeight` | `number` | `200` | 当内容较短时，编辑器将缩小到的最小高度（以像素为单位）。配对 `maxHeight` 设置自动增长范围。 |
| `maxHeight` | `number` | `500` | 编辑器在非全屏模式下可以增长到的最大高度（以像素为单位）。一旦内容超过此高度，编辑器内就会出现滚动条。该编辑器还有一个拖动手柄，因此用户可以手动将其大小调整到超出此限制。 |
| `renderer` | `function` | `marked` | 替换用于预览的 Markdown 解析器。接收 markdown 字符串并且必须返回 HTML 字符串。 |
| `sanitizer` | `function` | `DOMPurify` | 取代 HTML 清理程序。接收渲染的 HTML，并且必须返回安全的 HTML 来显示。 |
| `onChange` | `function` | `undefined` | 每次内容更改时都会触发回调：键入、工具栏操作、撤消/重做和列表延续。接收当前的 markdown 字符串作为其唯一的参数。 |
| `labels` | `object` | `undefined` | 编辑器自己界面的翻译，由英文字符串键入。您遗漏的任何内容都将保留为英文。 |

</DocTable>

##### 💡实施技巧：

- **重新排序**：按钮按照您在数组中列出的确切顺序显示
- **删除**：只需省略任何键（例如 `image`) 从数组中完全为用户禁用该功能
- **本机后备**：如果您不提供 `placeholder` 在 JS 中，插件会自动使用 `placeholder` 来自 HTML 的属性 `<textarea>`

### 🧩 自定义工具

添加您自己的工具栏按钮，无需分叉。描述它并将其放入 `toolbar` 数组，在任何你想要的位置。

<Snippet view="code">

```javascript
new MarkdownEditor('#markdown-editor', {
    toolbar: ['bold', 'italic', {
        custom: {
            title: 'Callout',
            icon: '<svg xmlns="http://www.w3.org/2000/svg" width="20" height="20">…</svg>',
            action(editor) {
                editor.insertText('> [!NOTE]\n> Something worth noting');
            }
        }
    }, 'preview']
});
```

</Snippet>

这 `title` 成为工具提示和按钮的 CSS 类，因此这个样式可设置为 `.callout-btn`，与内置工具完全相同。

#### 几个工具

添加任意数量。每个工具都是数组中自己的条目，因此您可以单独放置它们，并且它们可以位于内置工具之间，而不是分组在一端。

<Snippet view="code">

```javascript
toolbar: [
    'bold', 'italic',
    { custom: { title: 'Callout',   icon: svg1, action: insertCallout } },
    'ul', 'ol',
    { custom: { title: 'Signature', icon: svg2, action: insertSignature } },
    'preview'
]
```

</Snippet>

赋予每一个独特的 `title`。共享同一个标题的两个工具将共享一个 CSS 类，而没有标题的工具会退回到 `.custom-btn`.

#### 选项

<DocTable wrapper="overflow-x-auto w-full not-prose" table="table table-md">

| 财产 | 类型 | 目的 |
| --- | --- | --- |
| `title` | `string` | 必需的。工具提示文本和按钮 CSS 类的源。可翻译通过 `labels`. |
| `action` | `function` | 必需的。收到 `(editor, event)`。单击事件被传递，以便打开对话框的工具可以将其传递给 `MarkdownEditor.modal`. |
| `icon` | `string` | 按钮面的内联 SVG。 |
| `shortcut` | `string` | 键盘快捷键，例如 `Ctrl+Shift+K`。添加到工具提示，并优先于使用相同键的内置工具提示。 |

</DocTable>

一个工具没有 `action` 会跳过并显示控制台警告，而不是破坏工具栏。它不渲染任何按钮，并且它的 `shortcut`，如果它声明了，也没有注册。

#### 处理内容

使用 `editor.insertText()` 而不是自己写入文本区域。它替换选择、恢复焦点、移动插入符、滚动、重新渲染预览并触发 `onChange`。撤消操作仍然有效，因为编辑是通过正常路径进行的。

<Snippet view="code">

```javascript
action(editor) {
    const textarea = editor.usertextarea;
    const selected = textarea.value.slice(textarea.selectionStart, textarea.selectionEnd);
    const wrapped = `==${selected || 'highlight'}==`;

    // (text, where the caret lands, characters to leave outside the selection)
    editor.insertText(wrapped, wrapped.length, 0);
}
```

</Snippet>

#### 快捷方式

<Snippet view="code">

```javascript
{ custom: {
    title: 'Highlight',
    icon: '<svg>…</svg>',
    shortcut: 'Ctrl+Shift+H',
    action: (editor) => editor.insertText('====', 2, 2)
}}
```

</Snippet>

工具提示变为“突出显示 (Ctrl+Shift+H)”。工具快捷方式会在内置快捷方式之前进行检查，因此自定义工具可以故意接管编辑器本来可以处理的组合。

#### 需要自己标记的工具

下拉列表或对话框无法以声明方式描述，因此请编写一个类。延长 `MarkdownEditor.Tool`， 放 `this.button` 在构造函数中，并实现 `applySyntax()`.

<Snippet view="code">

```javascript
class EmbedTool extends MarkdownEditor.Tool {
    constructor(editor) {
        super(editor, 'Embed video');        // tooltip, and .embed-video-btn
        this.shortcut = 'Ctrl+Shift+E';      // optional
        this.button = this.createButton('<svg>…</svg>');
    }

    applySyntax(event) {
        const dialog = MarkdownEditor.modal(event, 'fj:max-w-sm', `
            <input type="url" class="embed-url fj:me-input fj:w-full">
            <button type="button" class="embed-go fj:me-btn fj:me-btn-sm">Insert</button>
        `, 'Embed');

        dialog.querySelector('.embed-go').addEventListener('click', () => {
            const url = dialog.querySelector('.embed-url').value.trim();
            if (url) this.editor.insertText(`\n<iframe src="${url}"></iframe>\n`);
            dialog.close();
        });
    }

    destroy() {
        // Called by editor.destroy(). Release anything you registered here.
    }
}

new MarkdownEditor('#markdown-editor', { toolbar: ['bold', EmbedTool, 'preview'] });
```

</Snippet>

通过配置 `{ tool: EmbedTool, config: {...} }`，它作为构造函数的第二个参数到达。环境 `this.button` 到 `null` 不渲染任何内容，这对于仅适用于某些配置的工具很有用。

需要注意的一件事： `Tool`的构造函数调用 `createButton()`，所以你的覆盖需要的任何东西都必须来自 `this.editor`，不是来自您之后分配的字段 `super()`.

#### 对话框助手

`MarkdownEditor.modal` 是内置链接和图像工具使用的对话框，因此您收集输入的工具看起来就像编辑器的其余部分，而不是发明自己的弹出窗口。它返回 `<dialog>` 元素，已打开，您可以查询字段并用其关闭 `dialog.close()`.

<Snippet view="code">

```javascript
// (event, size classes, body HTML, aria label)
const dialog = MarkdownEditor.modal(event, 'fj:max-w-sm', '…', 'Embed');
```

</Snippet>

通过 `event` 你的 `applySyntax()` 已收到。帮助器读取它以查找单击来自哪个编辑器，因此该对话框将附加到该编辑器的包装器内并选择其主题。它会替换该编辑器中已打开的所有对话框，并在关闭时将其自身从 DOM 中删除，因此无需清理任何内容。

#### 自己渲染 Markdown

如果您的工具嵌入了渲染内容（例如工具提示主体）， `editor.renderMarkdown()` 生成与预览完全相同的 HTML，尊重您的 `renderer` 和 `sanitizer`.

<Snippet view="code">

```javascript
const html = editor.renderMarkdown('**bold** text');
```

</Snippet>

#### 您自己的文本区域的工具栏

当对话框收集富文本时，为其提供真正的格式化工具，而不是重建它们。工具栏绑定到您传递的文本区域，您的 `labels` 都是继承的，并且没有添加预览按钮。

<Snippet view="code">

```javascript
const body = dialog.querySelector('textarea');
const bar = editor.createToolbar(body, ['bold', 'italic', 'strikethrough']);
dialog.querySelector('.body-toolbar').appendChild(bar);
```

</Snippet>

这不会管理工具栏的生命周期。当对话框被删除时，这些按钮会随着对话框一起清理，但是如果其中的工具注册了页面范围内的任何内容、文档侦听器或计时器，请在对话框关闭时自行释放它们。

#### 翻译

自定义工具可以像内置工具一样进行翻译，由您赋予它们的标题键入。

<Snippet view="code">

### 📊 页脚（状态栏）

页脚位于编辑器下方，显示光标的**行**、**列**、文档的**字符数**以及可选的**字数**，所有这些都是实时更新的。默认情况下它是可见的，并且每个统计数据都可以独立切换。

| --- | --- | --- | --- |

| `chars` | `boolean` | `true` | 显示总字符数。 |
| `words` | `boolean` | `false` | 显示总字数。默认关闭：设置为 `true` 启用。 |

<Snippet view="code">

</Snippet>

### 🏷 变量

添加用于插入占位符的工具栏下拉列表。当编写文档的人不是定义占位符语法的开发人员时很有用，例如电子邮件、发票或合同模板：他们选择一个可读的名称，并为其插入正确的语法。

<Snippet view="code">

```javascript
new MarkdownEditor('#markdown-editor', {
    toolbar: ['bold', 'italic', 'link',
        { variables: [
            { label: 'Customer Name', value: '{{customer.name}}' },
            { label: 'Invoice No',    value: '{{invoice.number}}' }
        ]},
        'preview'
    ]
});
```

</Snippet>

该工具是内联配置的 `toolbar` 数组，因此它在其他按钮中的位置取决于您。该按钮列出了标签，单击其中一个即可插入其标签 `value` 在光标处，替换任何选择。如果列表为空，则不会呈现任何内容。

#### 预览中的示例值

给定一个条目 `sample` 在预览中显示该示例，而文本区域保留真实的占位符。没有其中之一的条目将按书面形式显示，因此您可以将两者混合使用。

<Snippet view="code">

```javascript
{ variables: [
    { label: 'Customer Name', value: '{{customer.name}}', sample: 'Hannes' },
    { label: 'Invoice No',    value: '{{invoice.number}}' }
]}

// textarea : Hi {{customer.name}}, invoice {{invoice.number}}
// preview  : Hi Hannes, invoice {{invoice.number}}
```

</Snippet>

#### 分组

给出一个条目 `items` 而不是 `value` 渲染一个有标题的部分。分组条目和平面条目可以混合在一个列表中。

<Snippet view="code">

```javascript
{ variables: [
    { label: 'Today', value: '{{today}}', sample: '10 September 2026' },
    { label: 'Customer', items: [
        { label: 'Name',  value: '{{customer.name}}',  sample: 'Hannes' },
        { label: 'Email', value: '{{customer.email}}', sample: 'hannes@example.com' }
    ]},
    { label: 'Invoice', items: [
        { label: 'Number', value: '{{invoice.number}}' }
    ]}
]}
```

</Snippet>

#### 要知道的事情

- **编辑器从不解析变量。** 它插入文本，然后您的应用程序通常在服务器端替换实际值。 `sample` 仅影响预览显示的内容。
- **标签显示为纯文本**，因此标签中的标记永远不会呈现。
- **格式错误的条目将被跳过**而不是抛出，并且当未配置任何可用的内容时，根本不会呈现按钮。

### 🖋 自定义渲染器

预览呈现为 [标记的](https://marked.js.org) 并用消毒 [DOM纯化](https://github.com/cure53/DOMPurify)。两者都可以更换。当您的应用程序已经使用另一个库呈现 Markdown 并且您希望预览与生产完全匹配时，请使用此选项。

这两个选项都是普通函数，它们接受一个字符串并返回一个字符串，因此任何解析器和任何清理程序都可以工作。

<Snippet view="code">

```javascript
import MarkdownIt from 'markdown-it';
import taskLists from 'markdown-it-task-lists';
import MarkdownEditor from 'markdown-text-editor';

const md = new MarkdownIt({ linkify: true, breaks: true }).use(taskLists);

new MarkdownEditor('#markdown-editor', {
    renderer: markdown => md.render(markdown)
});
```

</Snippet>

DOMPurify 仍然在输出上运行，因此您无需配置任何内容即可保持 XSS 保护。

#### 定制消毒液

仅当默认删除渲染器发出的内容时才需要。 DOMPurify 删除 `<iframe>` 默认情况下，因此视频嵌入需要明确允许。 DOMPurify 必须在您自己的代码中导入，因为与编辑器捆绑的副本是内部的。

<Snippet view="code">

```javascript
import DOMPurify from 'dompurify';

new MarkdownEditor('#markdown-editor', {
    renderer:  markdown => md.render(markdown),
    sanitizer: html => DOMPurify.sanitize(html, {
        ADD_TAGS: ['iframe'],
        ADD_ATTR: ['allow', 'allowfullscreen', 'frameborder']
    })
});
```

</Snippet>

使用脚本标签而不是捆绑器，将 DOMPurify 与编辑器一起加载：

<Snippet view="code">

```html
<script src="https://cdn.jsdelivr.net/npm/dompurify"></script>
<script src="https://cdn.jsdelivr.net/npm/markdown-text-editor"></script>
```

</Snippet>

#### 要知道的事情

- **仅限预览。** 混合模式的实时格式使用单独的内部渲染器，并且不受影响。
- **任务列表需要插件支持。**可通过查找找到可点击的复选框 `input[type="checkbox"]` 在输出中，所以 markdown-it 需要 `markdown-it-task-lists`。如果编辑器检测到任务列表语法且没有复选框，则会记录一条警告。
- **两者必须同步**并返回一个字符串。一个 `async` 函数写入 `[object Promise]` 进入预览。
- **更换消毒剂就取代了您的保护。** 传递，例如 `html => html` 完全禁用清理，并且仅对完全信任的内容是安全的。

### 🪟 全屏和分层（z-index）

在全屏模式下，编辑器使用 `z-index: 10000`，这会清除大多数 UI 框架为固定标题和覆盖层保留的层。如果固定标题或侧边栏仍然覆盖编辑器，请提高此值。

```css
/* every editor on the page */

#admin-panel {
    --mte-fullscreen-z-index: 20000;
}

/* a single editor, by its textarea id */
[data-editor="notes"] {
    --mte-fullscreen-z-index: 20000;
}
```

</Snippet>

## 内容API

**MarkdownEditor** 的核心优势之一是它保留了底层 `<textarea>` 完美同步。无论您使用现代 JavaScript 框架还是传统后端（例如 **Django、PHP 或 Laravel**），工作流程都保持简单且原生。

### 阅读和写作内容

#### 1\.本土方式（推荐）

由于编辑器增强了标准文本区域，因此您可以使用熟悉的 DOM 方法。这是无需学习新 API 即可与数据交互的最快方式。

<Snippet view="code">

```javascript
// Retrieve content via ID
const markdown = document.getElementById('markdown-editor').value;

// Set content via ID (The editor UI updates automatically)
document.getElementById('markdown-editor').value = "# New Heading Content";
```

</Snippet>

#### 2\.使用变量引用

如果您有对 textarea 元素的引用，则可以直接使用它：不需要特定于库的 API。

<Snippet view="code">

```javascript
const textarea = document.getElementById('markdown-editor');

// Retrieve content
const markdown = textarea.value;

// Set content (the editor UI reflects this immediately)
textarea.value = "## Updated via JS";
```

</Snippet>

#### 3\.设置初始内容服务器端

设置初始内容的推荐方法是直接在 `<textarea>` HTML：这可以自然地与每个后端框架（Django、Laravel、Rails、PHP 等）配合使用，并且编辑器会在 init 上自动呈现它。

<Snippet view="code">

```html
<!-- Recommended: set content server-side -->
<textarea id="markdown-editor"># Hello World</textarea>
```

</Snippet>

要在运行时读取或更新内容，请使用本机 `textarea` 价值。称呼 `editor.render()` 更新后刷新预览和混合层。

<Snippet view="code">

```javascript
const textarea = document.getElementById('markdown-editor');

// Read
const markdown = textarea.value;

// Update at runtime
textarea.value = '# New content';
editor.render();
```

</Snippet>

#### 4\.拆掉编辑器： `destroy()`

称呼 `editor.destroy()` 删除编辑器 DOM 包装并恢复原始状态 `<textarea>` 到其在文档中的位置。在单页应用程序中卸载视图时很有用。

<Snippet view="code">

```javascript
const editor = new MarkdownEditor('#markdown-editor');

// Remove the editor and restore the plain textarea
editor.destroy();
```

</Snippet>

### 对变化做出反应 `onChange`

通过一个 `onChange` 每次内容更改时都会收到回调通知。接收当前的 Markdown 字符串。

<Snippet view="code">

```javascript
const editor = new MarkdownEditor('#markdown-editor', {
    onChange(value) {
        console.log('Content changed:', value.length, 'characters');
    }

```

</Snippet>

#### 草稿自动保存 `localStorage`

使用 `onChange` 每次击键时保存草稿。在初始化编辑器之前通过预填充文本区域来恢复它。

<Snippet view="code">

```javascript
const DRAFT_KEY = 'my-page-draft';

// Restore saved draft before init (only if textarea starts empty)
const textarea = document.getElementById('markdown-editor');
const saved = localStorage.getItem(DRAFT_KEY);
if (saved && !textarea.value) textarea.value = saved;

// Save on every change
const editor = new MarkdownEditor('#markdown-editor', {
    onChange(value) {
        localStorage.setItem(DRAFT_KEY, value);
    }
});

// Clear draft after successful form submission
document.querySelector('form').addEventListener('submit', () => {
    localStorage.removeItem(DRAFT_KEY);
});
```

</Snippet>

### 表格提交

因为 **MarkdownEditor** 是直接构建在原生之上的 `<textarea>`，它开箱即用，与每个后端框架（Django、Laravel、PHP、Ruby on Rails 等）兼容。

这就是“本地优先”理念的闪光点。您无需在提交表单之前手动同步数据。浏览器将编辑器视为标准输入字段。

<Snippet view="code">

```html
<form method="POST" action="/api/submit">
  <textarea id="markdown-editor" name="content" class="h-48" rows="5">
    # Initial Content
  </textarea>

  <button type="submit">Submit to Server</button>

  // Just initialize it. That's it.
  new MarkdownEditor('#markdown-editor');
</script>
```

</Snippet>

只需使用标准 HTML `<form>`。这 `name` 文本区域上的属性是您的服务器将用来识别内容的属性。

##### 🚀 为什么它会改变后端的游戏规则

由于编辑器保留了原生 `<textarea>` 行为，您的服务器将数据作为标准字符串处理。需要零额外逻辑：没有 `preventDefault()` 并且没有说明书 `FormData` 建造。

##### 💡 为什么这是一个“杀手级功能”：

大多数编辑器（如 Quill、Editor.js、simpleMDE、easyMDE）以复杂的 JSON 结构保存数据。如果开发人员使用这些，他们必须重写他们的数据库模式和渲染逻辑。

使用 **MarkdownEditor**，开发人员可以使用旧网站，替换普通网站 `<textarea>` 与您的编辑器一起使用，**后端甚至不知道它发生了变化**。它只是收到与往常相同的原始文本，但用户获得了 10 倍更好的体验。

## 🖼️ 高级图像上传

本地处理图像上传：而​​不是依赖缓慢、占用大量内存的 Base64 字符串，这对于性能和 SEO 来说都是一个重大胜利。

### 粘贴和放置

将屏幕截图粘贴到编辑器中或将图像文件拖到编辑器中，然后通过与工具栏按钮相同的端点上传。占位符会立即出现，因此编辑器不会看起来冻结，并且一旦上传落地，它就会被替换为真实路径。如果上传失败，占位符将替换为可见标记，而不是默默消失。

这需要 `uploadUrl` 配置如下。如果没有它，粘贴图像不会执行任何操作，并且编辑器会记录一条警告，解释要添加的内容，因为替代方案将是数据库中的 Base64 字符串。

一次上传多个文件，因此图像按照到达的顺序排列。

### 配置选项

图像工具支持 `fileInput` 配置来处理直接服务器上传。

-   `accept`：定义允许的图像格式数组（例如“webp”、“avif”）
-   `uploadUrl`：指定后端端点 `File` 对象将通过发送 `POST`
-   `params`：可选对象，用于与图像文件一起发送附加数据（例如 CSRF 令牌、用户 ID 或文件夹名称）

### 使用示例（完整配置）

<Snippet view="code">

```javascript
const options = {
  placeholder: 'Start writing...',
  toolbar: [
    'link',
    {
      image: {
        fileInput: {
            accept: ['webp', 'avif'], // restrict the image upload format
            uploadUrl: '/api/upload', // Your upload endpoint
            params: {
                _token: 'your_csrf_token_here', // Essential for Laravel/Django
                folder: 'blog_posts'
            }
        },
        // Supports boolean: true/false OR object: { required: true }
        altInput: { required: true }
      }
    },
    'preview'
  ],
}
const editor = new MarkdownEditor('#markdown-editor', options);
```

</Snippet>

### 📡 服务器集成

#### 请求

编辑发来一条 `POST` 请求为 `multipart/form-data`。默认情况下，它包括：

-   `image_file`: 实际的文件对象
-   `image_alt`：用户输入的替代文本
- ...加上中定义的任何自定义数据 `params` 目的

#### 所需的回应

要确认上传成功并将图像插入编辑器，您的服务器**必须**返回以下 JSON 结构：

<Snippet view="code">

```json
{
  "success": true,
  "image_path": "https://cdn.yourdomain.com/uploads/image.webp"
}
```

</Snippet>

**注意**：确保您使用密钥 `image_path` 为上传图像的 URL。

您也可以返回 `image_alt`，仅当用户将 alt 字段留空时才用作建议。他们自己输入的任何内容总是会获胜，因此从文件名或图像识别中派生替代文本的服务器可以在不覆盖真实描述的情况下提供替代文本。

<Snippet view="code">

```json
{
  "success": true,
  "image_path": "https://cdn.yourdomain.com/uploads/image.webp",
  "image_alt": "Two people looking at a laptop"
}
```

</Snippet>

失败时返回 `success: false` 与一个 `error` 或者 `message` 细绳。该文本会呈现给用户，因此请使其成为他们可以采取行动的内容。

### 图像替代文本验证（`altInput`)

为了确保您的内容保持可访问性和 SEO 友好性，**MarkdownEditor** 默认强制执行替代文本验证。

- **默认行为**：如果 `altInput` 没有定义，默认为 `{ required: true }`
- **强制可访问性**：在提供替代说明之前，将阻止用户插入图像

#### 1\.默认（无需配置）

<Snippet view="code">

```javascript
// Alt text is REQUIRED by default
image: {
  fileInput: { uploadUrl: '/api/upload' }
}
```

</Snippet>

#### 2\.速记（禁用验证）

如果您想允许没有描述的图像，只需将布尔值设置为 `false`.

<Snippet view="code">

```javascript
image: {
  altInput: false // Users can now skip the alt text field
}
```

</Snippet>

#### 3\.基于对象（显式）

<Snippet view="code">

```javascript
image: {
    altInput: {
        required: false // Disables alt text validation — users can skip the alt field
    }
}
```

</Snippet>

### 标准图像使用（否 `fileInput`)

如果 `fileInput` 未配置时，编辑器默认为简单的基于 URL 的模式。如果您的用户主要链接到外部图像主机，那么这是理想的选择。

<Snippet view="code">

```javascript
const options = {
  toolbar: [
    'link',
    'image',
    'preview'
  ],
}
const editor = new MarkdownEditor('#markdown-editor', options);
```

</Snippet>

### 💡 为什么使用参数？

在 Laravel 或 Django 等框架中，如果没有 CSRF 令牌，则无法上传文件。通过添加 `_token` 到 `params` 对象，您的请求将无缝地通过后端的安全中间件，维护服务器端控制器的“零逻辑”理念。
