<h2>The Philosophy: "Native-First"</h2>
<p>Most editors break the standard web workflow. <strong>MarkdownEditor</strong> embraces it.
Because it sits directly on top of a <code>&lt;textarea&gt;</code>, you don't need to learn a new way to handle data.</p>
<ul>
    <li><strong>No Data Binding Needed: </strong>Works with <code>&lt;form method="POST"&gt;</code> out of the box</li>
    <li><strong>Standard Access:</strong> Use <code>document.getElementById('editor').value</code> just like a normal input.</li>
    <li><strong>Backend Agnostic:</strong> Works with any backend (Python, Node.js, PHP, etc.) just like a normal form field</li>
</ul>

<h2>MarkdownEditor vs EasyMDE / SimpleMDE</h2>
<p>Most JavaScript markdown editors — EasyMDE, SimpleMDE, CodeMirror-based editors — <strong>replace your <code>&lt;textarea&gt;</code></strong> with a custom element. That means form submission breaks, <code>.value</code> returns nothing, and you have to write extra code just to read the content back out. <strong>MarkdownEditor is different</strong> — it enhances your existing textarea and never replaces it.</p>

<h2>Framework Integration</h2>
<p>Because <strong>MarkdownEditor</strong> preserves the native <code>&lt;textarea&gt;</code>, it integrates with every backend framework without any extra code. Your server receives the markdown content exactly as it would from any standard form field. For React and Vue it takes a few lines, covered at the end of this section.</p>

<h3>Django</h3>
<p>Add a <code>class</code> to your textarea widget and initialize the editor — <code>request.POST['content']</code> works with no extra steps.</p>

```python
# forms.py
class PostForm(forms.ModelForm):
    class Meta:
        model = Post
        fields = ['content']
        widgets = {
            'content': forms.Textarea(attrs={'class': 'markdown-editor'}),
        }
```


```javascript
new MarkdownEditor('.markdown-editor');
// request.POST['content'] contains the markdown on submit
```


<h3>Laravel</h3>
<p>Use <code>f.text_area</code> with a class — <code>$request->input('content')</code> receives the markdown directly.</p>

```html
<textarea name="content" class="markdown-editor"></textarea>
```


<h3>Ruby on Rails</h3>
<p>Works with <code>form_with</code> out of the box — <code>params[:content]</code> contains the markdown. For Turbo Drive, use <code>turbo:load</code> instead of <code>DOMContentLoaded</code>.</p>

```javascript
document.addEventListener('turbo:load', () => {
    document.querySelectorAll('.markdown-editor:not([data-mde-init])').forEach(el => {
        el.setAttribute('data-mde-init', 'true');
        new MarkdownEditor(el);
    });
});
```

<h3>React</h3>
<p>Create the editor in an effect and destroy it on unmount. Use <code>defaultValue</code> rather than <code>value</code>: the editor writes to the textarea directly, so a controlled binding would overwrite what the user is typing.</p>

```javascript
import { useEffect, useRef } from 'react';
import MarkdownEditor from 'markdown-text-editor';

function MarkdownField({ name, defaultValue = '', onChange }) {
    const ref = useRef(null);

    useEffect(() => {
        const editor = new MarkdownEditor(ref.current, { onChange });
        return () => editor.destroy();
    }, []);

    return &lt;textarea ref={ref} name={name} defaultValue={defaultValue} /&gt;;
}
```

<p>Returning <code>editor.destroy()</code> from the effect also covers StrictMode, which runs effects twice in development and would otherwise leave two editors on one textarea. The empty dependency array is deliberate: options are read once when the editor is created, so re-running the effect would tear it down and rebuild it on every change.</p>

<h3>Vue</h3>
<p>Same idea. Set the initial value once in <code>onMounted</code> and do not bind <code>:value</code>, or every keystroke emitted back through <code>v-model</code> would overwrite the textarea.</p>

```javascript
&lt;script setup&gt;
import { ref, onMounted, onBeforeUnmount } from 'vue';
import MarkdownEditor from 'markdown-text-editor';

const el = ref(null);
const props = defineProps({ modelValue: { type: String, default: '' } });
const emit = defineEmits(['update:modelValue']);
let editor = null;

onMounted(() => {
    el.value.value = props.modelValue;
    editor = new MarkdownEditor(el.value, {
        onChange: value =&gt; emit('update:modelValue', value)
    });
});

onBeforeUnmount(() =&gt; editor?.destroy());
&lt;/script&gt;

&lt;template&gt;&lt;textarea ref="el"&gt;&lt;/textarea&gt;&lt;/template&gt;
```

<p>Used as <code>&lt;MarkdownField v-model="content" /&gt;</code>. In a plain form you can skip <code>v-model</code> entirely and read the value from the textarea on submit, as with any other framework.</p>

<ul>
    <li><strong>Reordering</strong>: The buttons appear in the exact order you list them in the array</li>

<h4>Usage Examples</h4>

```javascript
// Default — line, col, and chars visible
new MarkdownEditor('#editor');

// Disable the footer entirely
new MarkdownEditor('#editor', { footer: false });

// Hide only character count
new MarkdownEditor('#editor', { footer: { chars: false } });

// Hide line and column, keep character count
new MarkdownEditor('#editor', { footer: { line: false, col: false } });

// Show only line number
new MarkdownEditor('#editor', { footer: { col: false, chars: false } });

// Enable word count alongside the defaults
new MarkdownEditor('#editor', { footer: { words: true } });

// Show word count only
new MarkdownEditor('#editor', { footer: { line: false, col: false, chars: false, words: true } });
```


<h3>🔀 Editing Modes</h3>
<p><strong>MarkdownEditor</strong> offers two distinct ways to write and format your content. You can toggle between a traditional syntax-focused view or a modern, visual-first experience.</p>
<ul>
    <li><code>plain</code> (<strong>Default</strong>): A clean, high-performance Markdown environment where syntax (like <code>**bold**</code> or <code># heading</code>) is visible. Ideal for developers and Markdown purists</li>
    <li><code>hybrid</code>: A WYSIWYG-inspired experience that renders formatting (Bold, Italics, Headings) in real-time as you type, while still maintaining the underlying Markdown structure.</li>
</ul>


```javascript
// Default initialization (Plain Mode)
new MarkdownEditor('#markdown-editor');

// Explicit Plain Mode
new MarkdownEditor('#markdown-editor', {
    mode: 'plain'
});

// Hybrid (Visual) Mode
new MarkdownEditor('#markdown-editor', {
    mode: 'hybrid'
});
```

<h3>🌙 Theming</h3>
<p><strong>MarkdownEditor</strong> automatically inherits its theme from the surrounding page — no configuration required. The editor reads <code>data-theme</code> from the nearest ancestor at initialisation, so it stays in sync with your site's theme out of the box.</p>

<h4>How theme is resolved (priority order)</h4>
<ol>
    <li><strong><code>theme</code> option</strong> — explicit override passed in the options object</li>
    <li><strong><code>data-theme</code> on the <code>&lt;textarea&gt;</code></strong> — set directly on the element</li>
    <li><strong><code>data-theme</code> on any ancestor</strong> — e.g. <code>&lt;html&gt;</code>, <code>&lt;body&gt;</code>, or a wrapper <code>&lt;div&gt;</code></li>
</ol>

<h4>Available themes</h4>
<p><code>'light'</code> (default), <code>'dark'</code>, <code>'snowberry'</code>, <code>'darkberry'</code></p>

<h5>Option 1 — inherit from <code>&lt;html&gt;</code> or any ancestor (zero config)</h5>

```html
<html data-theme="dark">
  ...
  <textarea id="markdown-editor"></textarea>
```


<h5>Option 2 — set <code>data-theme</code> directly on the <code>&lt;textarea&gt;</code></h5>

```html
<textarea id="markdown-editor" data-theme="dark"></textarea>
```


<h5>Option 3 — explicit <code>theme</code> option (overrides everything)</h5>

```javascript
new MarkdownEditor('#markdown-editor', {
    theme: 'dark'
});
```

<p>Adds a toolbar dropdown for inserting placeholders. Useful when the person writing a document is not the developer who defined the placeholder syntax, as with email, invoice or contract templates: they pick a readable name and the correct syntax is inserted for them.</p>

```javascript
new MarkdownEditor('#markdown-editor', {
```

<h4>Sample values in the preview</h4>
<p>An entry given a <code>sample</code> shows that sample in the preview, while the textarea keeps the real placeholder. Entries without one appear as written, so you can mix both.</p>


```javascript

    { label: 'Customer Name', value: '', sample: 'Hannes' },

// preview  : Hi Hannes, invoice
```

<h4>Grouping</h4>
<p>Give an entry <code>items</code> instead of a <code>value</code> to render a headed section. Grouped and flat entries can be mixed in one list.</p>


```javascript

    { label: 'Today', value: '', sample: '10 September 2026' },
    { label: 'Customer', items: [
        { label: 'Name',  value: '',  sample: 'Hannes' },
```

<h4>Things to know</h4>
<ul>
    <li><strong>The editor never resolves variables.</strong> It inserts text, and your application substitutes real values later, usually server-side. <code>sample</code> only affects what the preview displays.</li>
    <li><strong>Labels are shown as plain text</strong>, so markup in a label is never rendered.</li>
    <li><strong>Malformed entries are skipped</strong> rather than throwing, and the button is not rendered at all when nothing usable is configured.</li>
</ul>

<h3>🖋 Custom Renderer</h3>
<p>The preview is rendered with <a href="https://marked.js.org" target="_blank">marked</a> and sanitized with <a href="https://github.com/cure53/DOMPurify" target="_blank">DOMPurify</a>. Both can be replaced. Use this when your application already renders markdown with another library and you want the preview to match production exactly.</p>

<p>Both options are plain functions that take a string and return a string, so any parser and any sanitizer works.</p>


```javascript
import MarkdownIt from 'markdown-it';
import taskLists from 'markdown-it-task-lists';
import MarkdownEditor from 'markdown-text-editor';

const md = new MarkdownIt({ linkify: true, breaks: true }).use(taskLists);

new MarkdownEditor('#markdown-editor', {
    renderer: markdown => md.render(markdown)
});
```


<p>DOMPurify still runs on the output, so you keep XSS protection without configuring anything.</p>

<h4>Custom sanitizer</h4>
<p>Only needed when the default strips something your renderer emits. DOMPurify removes <code>&lt;iframe&gt;</code> by default, so video embeds need it allowed explicitly. DOMPurify must be imported in your own code, since the copy bundled with the editor is internal.</p>


```javascript
import DOMPurify from 'dompurify';

new MarkdownEditor('#markdown-editor', {
    renderer:  markdown => md.render(markdown),
    sanitizer: html => DOMPurify.sanitize(html, {
        ADD_TAGS: ['iframe'],
        ADD_ATTR: ['allow', 'allowfullscreen', 'frameborder']
    })
});
```

<h4>Things to know</h4>
<ul>
    <li><strong>Preview only.</strong> Hybrid mode's live formatting uses a separate internal renderer and is not affected.</li>
    <li><strong>Task lists need plugin support.</strong> Clickable checkboxes are found by looking for <code>input[type="checkbox"]</code> in the output, so markdown-it needs <code>markdown-it-task-lists</code>. The editor logs a warning if it detects task list syntax and no checkboxes.</li>
    <li><strong>Both must be synchronous</strong> and return a string. An <code>async</code> function writes <code>[object Promise]</code> into the preview.</li>
    <li><strong>Replacing the sanitizer replaces your protection.</strong> A pass-through such as <code>html =&gt; html</code> disables sanitizing entirely and is only safe for fully trusted content.</li>

<h2>Content API</h2>
<p>One of the core strengths of <strong>MarkdownEditor</strong> is that it keeps the underlying <code>&lt;textarea&gt;</code> perfectly synchronized. Whether you are using a modern JavaScript framework or a traditional backend like <strong>Django, PHP, or Laravel</strong>, the workflow remains simple and native.</p>

<h3>Reading and Writing Content</h3>

<h4>1. The Native Way (Recommended)</h4>
<p>Because the editor enhances a standard textarea, you can use familiar DOM methods. This is the fastest way to interact with your data without learning a new API.</p>

```javascript
// Retrieve content via ID
const markdown = document.getElementById('markdown-editor').value;

// Set content via ID (The editor UI updates automatically)
document.getElementById('markdown-editor').value = "# New Heading Content";
```


<h4>2. Using a Variable Reference</h4>
<p>If you have a reference to the textarea element, you can use it directly — no library-specific API needed.</p>

```javascript
const textarea = document.getElementById('markdown-editor');

// Retrieve content
const markdown = textarea.value;

// Set content (the editor UI reflects this immediately)
textarea.value = "## Updated via JS";
```


<h4>3. Setting initial content server-side</h4>
<p>The recommended way to set initial content is directly in the <code>&lt;textarea&gt;</code> HTML — this works naturally with every backend framework (Django, Laravel, Rails, PHP, etc.) and the editor renders it automatically on init.</p>

```html
{/* Recommended: set content server-side */}
<textarea id="markdown-editor"># Hello World</textarea>
```


<p>To read or update content at runtime, use the native <code>textarea</code> value. Call <code>editor.render()</code> after an update to refresh the preview and hybrid layer.</p>

```javascript
const textarea = document.getElementById('markdown-editor');

// Read
const markdown = textarea.value;

// Update at runtime
textarea.value = '# New content';
editor.render();
```


<h4>4. Tearing down the editor — <code>destroy()</code></h4>
<p>Call <code>editor.destroy()</code> to remove the editor DOM wrapper and restore the original <code>&lt;textarea&gt;</code> to its position in the document. Useful in single-page applications when unmounting a view.</p>

```javascript
const editor = new MarkdownEditor('#markdown-editor');

// Remove the editor and restore the plain textarea
editor.destroy();
```


<h3>Reacting to changes with <code>onChange</code></h3>
<p>Pass an <code>onChange</code> callback to be notified on every content change. Receives the current markdown string.</p>

```javascript
const editor = new MarkdownEditor('#markdown-editor', {
    onChange(value) {
        console.log('Content changed:', value.length, 'characters');
    }
});
```


<h4>Draft auto-save with <code>localStorage</code></h4>
<p>Use <code>onChange</code> to save a draft on every keystroke. Restore it by pre-filling the textarea before initialising the editor.</p>

```javascript
const DRAFT_KEY = 'my-page-draft';

// Restore saved draft before init (only if textarea starts empty)
const textarea = document.getElementById('markdown-editor');
const saved = localStorage.getItem(DRAFT_KEY);
if (saved && !textarea.value) textarea.value = saved;

// Save on every change
const editor = new MarkdownEditor('#markdown-editor', {
    onChange(value) {
        localStorage.setItem(DRAFT_KEY, value);
    }
});

// Clear draft after successful form submission
document.querySelector('form').addEventListener('submit', () => {
    localStorage.removeItem(DRAFT_KEY);
});
```

<h2>🖼️ Advanced Image Upload</h2>
<p>Handling image uploads natively—rather than relying on slow, memory-heavy Base64 strings—is a significant win for both performance and SEO.</p>

<h3>Configuration Options</h3>
<p>The image tool supports a <code>fileInput</code> configuration to handle direct server uploads.</p>
<ul>
    <li><code>accept</code>: Define an array of allowed image formats (e.g., 'webp', 'avif')</li>
    <li><code>uploadUrl</code>: Specify the backend endpoint where the <code>File</code> object will be sent via <code>POST</code></li>
    <li><code>params</code>: Optional object to send additional data (like CSRF tokens, user IDs, or folder names) alongside the image file</li>
</ul>

<h3>Usage example (Full Config)</h3>

```javascript
const options = {
  placeholder: 'Start writing...',
  toolbar: [
    'link',
    {
      image: {
        fileInput: {
            accept: ['webp', 'avif'], // restrict the image upload format
            uploadUrl: '/api/upload', // Your upload endpoint
            params: {
                _token: 'your_csrf_token_here', // Essential for Laravel/Django
                folder: 'blog_posts'
            }
        },
        // Supports boolean: true/false OR object: { required: true }
        altInput: { required: true }
      }
    },
    'preview'
  ],
}
const editor = new MarkdownEditor('#markdown-editor', options);
```


<h3>📡 Server Integration</h3>
<h4>The Request</h4>
<p>The editor sends a <code>POST</code> request as <code>multipart/form-data</code>. By default, it includes:</p>
<ul>
    <li><code>image_file</code>: The actual file object</li>
    <li><code>image_alt</code>: The alt text entered by the user</li>
    <li>...plus any custom data defined in the <code>params</code> object</li>
</ul>

<h4>The Required Response</h4>
<p>To confirm a successful upload and insert the image into the editor, your server <strong>must</strong> return the following JSON structure:</p>

```json
{
  "success": true,
  "image_path": "https://cdn.yourdomain.com/uploads/image.webp"
}
```

<p><strong>Note</strong>: Ensure you use the key <code>image_path</code> for the URL of the uploaded image.</p>

<h3>Image Alt Text Validation (<code>altInput</code>)</h3>
<p>To ensure your content remains accessible and SEO-friendly, <strong>MarkdownEditor</strong> enforces alt text validation by default.</p>
<ul>
    <li><strong>Default Behavior</strong>: If <code>altInput</code> is not defined, it defaults to <code>&#123; required: true &#125;</code></li>
    <li><strong>Enforce Accessibility</strong>: Users will be prevented from inserting an image until an alt description is provided</li>
</ul>

<h4>1. Default (No configuration needed)</h4>

```javascript
// Alt text is REQUIRED by default
image: {
  fileInput: { uploadUrl: '/api/upload' }
}
```


<h4>2. Shorthand (Disable Validation)</h4>
<p>If you want to allow images without descriptions, simply set the boolean to <code>false</code>.</p>

```javascript
image: {
  altInput: false // Users can now skip the alt text field
}
```


<h4>3. Object-based (Explicit)</h4>

```javascript
image: {
    altInput: {
        required: false // Disables alt text validation — users can skip the alt field
    }
}
```


<h3>Standard Image Usage (No <code>fileInput</code>)</h3>
<p>If <code>fileInput</code> is not configured, the editor defaults to a simple URL-based modal. This is ideal if your users are mostly linking to external image hosts.</p>

```javascript
const options = {
  toolbar: [
    'link',
    'image',
    'preview'
  ],
}

```
