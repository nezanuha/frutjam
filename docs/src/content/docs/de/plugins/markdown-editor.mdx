Ein Markdown-Editor, der Ihren Textbereich verbessert, anstatt ihn zu ersetzen. Daher funktionieren Formularübermittlung, Validierung und erforderliche Felder weiterhin. WYSIWYG- und einfache Markdown-Modi, Live-Vorschau, Suchen und Ersetzen, RTL-Unterstützung, dunkler Modus. Funktioniert eigenständig mit Django, Laravel, Rails, Node.js, PHP und jedem Stack.

**Kein Frutjam und kein Rückenwind erforderlich.** Die Stile sind gebündelt, sodass der Editor in jedes Projekt fällt.

## Die Philosophie: „Native-First“

Die meisten Editoren unterbrechen den Standard-Web-Workflow. **MarkdownEditor* * umarmt es. Weil es direkt auf einem `<textarea>`müssen Sie keinen neuen Umgang mit Daten erlernen.

-   **Keine Datenbindung erforderlich:** Funktioniert mit `<form method="POST">` Out of the Box
-   **Standardzugang:** Nutzung `document.getElementById('editor').value` wie bei einer normalen Eingabe.
-   **Backend Agnostic:** Funktioniert mit jedem Backend (Python, Node.js, PHP, etc.) wie ein normales Formularfeld

## MarkdownEditor vs. EasyMDE / SimpleMDE

Die meisten JavaScript-Markdown-Editoren (EasyMDE, SimpleMDE, CodeMirror-basierte Editoren) **verstecken Ihre `<textarea>`** und bearbeiten Sie eine Kopie, indem Sie den Inhalt zurückschreiben, wenn das Formular eingereicht wird. Das funktioniert solange, bis etwas anderes den Wert braucht: ein `required` feld, das der Browser nicht fokussieren kann, blockiert das Absenden vollständig, und `.value` oder `FormData` read before Submit gibt eine leere Zeichenfolge zurück, die HTMX, Turbo, Autosave und nicht gespeicherte Änderungen unterbricht. **MarkdownEditor ist anders.** Er formatiert den Textbereich, den Sie bereits haben, und belässt ihn als das Feld, in das Sie eingeben, damit der Wert in jedem Moment korrekt ist.

| Feature | MarkdownEditor | EasyMDE / SimpleMDE |
| --- | --- | --- |
| Nativer Textbereich erhalten | ✅ | ❌ Ausgeblendet, als Kopie bearbeitet |
| Arbeitet mit `required` Felder | ✅ | ❌ Browser blockiert das Absenden |
| `.value` vor dem Absenden korrigieren | ✅ | ❌ Leer, bis das Formular abgeschickt wird |
| Serialisiert mit `FormData`, htmx, Turbo | ✅ | ❌ Benötigt die eigene API des Editors |
| WYSIWYG-HYBRIDMODUS | ✅ | ❌ |
| Integriertes Suchen & Ersetzen | ✅ | ❌ |
| RTL-Unterstützung | Integriert | Über CodeMirror's `direction` Option |
| Inline-Ereignishandler (CSP) |     Keine | Einige |
| Dunkler Modus / Design | ✅ | Begrenzt |
| Bündelgröße, mit Reißverschluss | 41 KB JS + 13 KB CSS | 107 KB (JS + CSS) |

</DocTable>

### Reagieren

Erstellen Sie den Editor in einem Effekt und zerstören Sie ihn beim Abhängen. Verwenden `defaultValue` anstelle von `value`: der Editor schreibt direkt in den Textbereich, so dass eine kontrollierte Bindung überschreiben würde, was der Benutzer eingibt.

<Snippet view="code">

```javascript
import { useEffect, useRef } from 'react';
import MarkdownEditor from 'markdown-text-editor';

function MarkdownField({ name, defaultValue = '', onChange }) {
    const ref = useRef(null);

    // Options are read once at construction, so the editor would hold on to
    // whichever onChange it was handed first. A ref keeps it current.
    const onChangeRef = useRef(onChange);
    onChangeRef.current = onChange;

    useEffect(() => {
        const editor = new MarkdownEditor(ref.current, {
            onChange: (value) => onChangeRef.current?.(value),
        });
        return () => editor.destroy();
    }, []);

    return &lt;textarea ref={ref} name={name} defaultValue={defaultValue} /&gt;;
}
```

</Snippet>

Wird zurückgegeben `editor.destroy()` der Effekt deckt auch den StrictMode ab, der zweimal in der Entwicklung ist und ansonsten zwei Editoren auf einem Textfeld belassen würde. Das leere Abhängigkeitsarray ist bewusst: Optionen werden einmal gelesen, wenn der Editor erstellt wird, so dass ein erneutes Ausführen des Effekts ihn herunterreißen und bei jedem Rendering neu erstellen würde.

Das ist auch der Grund, warum `onChange` durchläuft eine Ref. Wenn Sie es direkt an den Konstruktor übergeben, wird der Editor an die Funktion angeheftet, die er auf dem Mount erhalten hat, und ein Inline-Pfeil im übergeordneten Element würde in dem Moment veraltet sein, in dem sich alles, was er schließt, ändert.

### GUE

Gleiche Idee. Setzen Sie den Anfangswert einmal in `onMounted` Und benutzen Sie `:value`oder jeder Tastendruck, der durch `v-model` würde den Textbereich überschreiben.

<Snippet view="code">

```javascript
&lt;script setup&gt;
import { ref, onMounted, onBeforeUnmount } from 'vue';
import MarkdownEditor from 'markdown-text-editor';

const el = ref(null);
const props = defineProps({ modelValue: { type: String, default: '' } });
const emit = defineEmits(['update:modelValue']);
let editor = null;

onMounted(() => {
    el.value.value = props.modelValue;
    editor = new MarkdownEditor(el.value, {
        onChange: value =&gt; emit('update:modelValue', value)
    });
});

onBeforeUnmount(() =&gt; editor?.destroy());
&lt;/script&gt;

&lt;template&gt;&lt;textarea ref="el"&gt;&lt;/textarea&gt;&lt;/template&gt;
```

</Snippet>

%1 auf %2 %3 muss %4 sein. Wenn %2 in %5 verwendet wird, wird die Wechselkursanpassung im %6-Feld in %7 definiert. %2 %3 wird im %8-Feld in %5 verwendet `<MarkdownField v-model="content" />`. In einer einfachen Form können Sie überspringen `v-model` vollständig und lesen Sie den Wert aus dem Textfeld bei der Einreichung, wie bei jedem anderen Framework.


### Serverseitiges Rendering

Das Importieren des Editors auf den Server wirft nicht, so dass Next.js, Remix, Nuxt und SvelteKit keine `dynamic(..., { ssr: false })` umwickeln.

Der Grund, warum es funktioniert, ist die obige Regel: Der Editor wird im Inneren erstellt `useEffect`, `onMounted` oder `onMount`, und keiner von ihnen wird auf dem Server ausgeführt. Die DOM-Arbeit bleibt im Browser.

<Snippet view="code">

```javascript
// app/page.tsx — a server component, nothing opted out of SSR
import MarkdownField from './MarkdownField';

export default function Page() {
    return (
        <form method="post">
            <MarkdownField name="content" defaultValue="# Hello" />
        </form>
    );
}
```

</Snippet>

Die `<textarea>` versendet im Server-HTML mit seinem Inhalt bereits in ihm, also gibt es nichts zu warten und nichts, das hereinspringt. React rendert das gleiche Markup auf beiden Seiten und der Editor verbessert es nach der Hydratation, so dass es keine Diskrepanz gibt, vor der man warnen muss.

Optionen werden einmal gelesen, wenn der Editor aufgebaut ist. Eine nachträgliche Änderung hat keine Auswirkung: Anruf `destroy()` und stattdessen einen neuen Editor erstellen.

#### Überschriften-Ebenen

Die `heading` dropdown-Angebote H1 bis H6. Wenn H1 zur Seite und nicht zum Inhalt gehört, was bei den meisten CMS-Body-Feldern der Fall ist, schränken Sie es ein:

<Snippet view="code">

```javascript
new MarkdownEditor('#markdown-editor', {
    toolbar: [{ heading: { levels: [2, 3, 4] } }, 'bold', 'italic', 'preview']
});
```

</Snippet>

`Ctrl+1`, `Ctrl+2` und `Ctrl+3` folgen Sie der gleichen Liste, so dass eine Ebene, die Sie auslassen, auch nicht von der Tastatur eingefügt werden kann, und der Tooltip der Schaltfläche listet nur die Verknüpfungen auf, die noch funktionieren. Die Reihenfolge, in der Sie sie schreiben, spielt keine Rolle, das Menü ist immer H1 zuerst. Ebenen außerhalb von 1 bis 6 werden mit einer Konsolenwarnung ignoriert, und eine Liste, in der nichts verwendbar ist, fällt auf alle sechs zurück, anstatt ein leeres Menü darzustellen.

Dies schränkt die Symbolleiste ein, nicht das Dokument. Jemand kann immer noch tippen `# Title` von Hand und es wird als Überschrift gerendert, denn was gültig ist, ist die Entscheidung des Renderers und nicht die der Symbolleiste. Wenn die Regel gelten muss, erzwingen Sie sie auf dem Server.

##### Implementierungstipps

-   ** Neu anordnen**: Die Schaltflächen werden in der genauen Reihenfolge angezeigt, in der Sie sie im Array auflisten
-   **Entfernen**: Lassen Sie einfach einen beliebigen Schlüssel (wie `image`) aus dem Array, um diese Funktion vollständig für den Benutzer zu deaktivieren
-   **Native Fallback**: Wenn Sie keine `placeholder` in JS verwendet das Plugin automatisch die `placeholder` attribut aus Ihrem HTML `<textarea>`

### Benutzerdefinierte Werkzeuge

Fügen Sie eine eigene Symbolleistenschaltfläche hinzu, ohne zu verzweigen. Beschreiben Sie es und legen Sie es in die `toolbar` array, in welcher Position Sie es auch immer haben möchten.

<Snippet view="code">

```javascript
new MarkdownEditor('#markdown-editor', {
    toolbar: ['bold', 'italic', {
        custom: {
            title: 'Callout',
            icon: '<svg xmlns="http://www.w3.org/2000/svg" width="20" height="20">…</svg>',
            action(editor) {
                editor.insertText('> [!NOTE]\n> Something worth noting');
            }
        }
    }, 'preview']
});
```

</Snippet>

Die `title` wird zum Tooltip und zur CSS-Klasse des Buttons, so dass dieser als `.callout-btn`, genau wie die eingebauten Werkzeuge.

#### - 4 Stück Werkzeuge

Fügen Sie so viele hinzu, wie Sie möchten. Jeder ist ein eigener Eintrag im Array, so dass Sie sie einzeln platzieren können und sie zwischen integrierten Tools sitzen können, anstatt an einem Ende gruppiert zu werden.

<Snippet view="code">

```javascript
toolbar: [
    'bold', 'italic',
    { custom: { title: 'Callout',   icon: svg1, action: insertCallout } },
    'ul', 'ol',
    { custom: { title: 'Signature', icon: svg2, action: insertSignature } },
    'preview'
]
```

</Snippet>

Geben Sie jedem ein unverwechselbares `title`. Zwei Tools, die einen Titel teilen, würden eine CSS-Klasse teilen, und ein Tool ohne einen fällt auf `.custom-btn`.

#### Optionen

<DocTable wrapper="overflow-x-auto w-full not-prose" table="table table-md">

| Property | Typ | Sinn |
| --- | --- | --- |
| `title` | `string` | Erforderlich. Tooltip-Text und die Quelle der CSS-Klasse des Buttons. Übersetzbar durch `locale`. |
| `action` | `function` | Erforderlich. Erhält `(editor, event)`. Das Klickereignis wird weitergegeben, damit ein Werkzeug, das einen Dialog öffnet, es an `MarkdownEditor.modal`. |
| `icon` | `string` | Inline-SVG für das Tastengesicht. |
| `shortcut` | `string` | Eine Tastenkombination wie `Ctrl+Shift+K`. Wird dem Tooltip hinzugefügt und hat Vorrang vor einem integrierten Tool mit denselben Tasten. |

</DocTable>

Ein Werkzeug ohne `action` wird mit einer Konsolenwarnung übersprungen, anstatt die Symbolleiste zu unterbrechen. Es gibt keine Schaltfläche aus, und seine `shortcut`, wenn es eine deklariert hat, ist auch nicht registriert.

#### Mit den Inhalten arbeiten

Gebrauch `editor.insertText()` anstatt selbst in den Textbereich zu schreiben. Es ersetzt die Auswahl, stellt den Fokus wieder her, verschiebt das Caret, scrollt, rendert die Vorschau neu und feuert `onChange`. Rückgängig funktioniert weiter, da die Bearbeitung den normalen Pfad durchläuft.

<Snippet view="code">

```javascript
action(editor) {
    const textarea = editor.usertextarea;
    const selected = textarea.value.slice(textarea.selectionStart, textarea.selectionEnd);
    const wrapped = `==${selected || 'highlight'}==`;

    // (text, where the caret lands, characters to leave outside the selection)
    editor.insertText(wrapped, wrapped.length, 0);
}
```

</Snippet>

#### Shortcuts

<Snippet view="code">

```javascript
{ custom: {
    title: 'Highlight',
    icon: '<svg>…</svg>',
    shortcut: 'Ctrl+Shift+H',
    action: (editor) => editor.insertText('====', 2, 2)
}}
```

</Snippet>

Der Tooltip wird zu "Hervorheben (Strg+Umschalt+H)". Tool-Verknüpfungen werden vor den eingebauten überprüft, so dass ein benutzerdefiniertes Tool absichtlich eine Kombination übernehmen kann, die der Editor sonst handhaben würde.

#### Tools, die ein eigenes Markup benötigen

Ein Dropdown oder ein Dialog kann nicht deklarativ beschrieben werden, schreiben Sie also stattdessen eine Klasse. Erweitern `MarkdownEditor.Tool`Garnitur `this.button` im Konstruktor und implementieren `applySyntax()`.

<Snippet view="code">

```javascript
class EmbedTool extends MarkdownEditor.Tool {
    constructor(editor) {
        super(editor, 'Embed video');        // tooltip, and .embed-video-btn
        this.shortcut = 'Ctrl+Shift+E';      // optional
        this.button = this.createButton('<svg>…</svg>');
    }

    applySyntax(event) {
        const dialog = MarkdownEditor.modal(event, 'fj:max-w-sm', `
            <input type="url" class="embed-url fj:me-input fj:w-full">
            <button type="button" class="embed-go fj:me-btn fj:me-btn-sm">Insert</button>
        `, 'Embed');

        dialog.querySelector('.embed-go').addEventListener('click', () => {
            const url = dialog.querySelector('.embed-url').value.trim();
            if (url) this.editor.insertText(`\n<iframe src="${url}"></iframe>\n`);
            dialog.close();
        });
    }

    destroy() {
        // Called by editor.destroy(). Release anything you registered here.
    }
}

new MarkdownEditor('#markdown-editor', { toolbar: ['bold', EmbedTool, 'preview'] });
```

</Snippet>

Pass-Konfiguration mit `{ tool: EmbedTool, config: {...} }`, das als zweites Argument des Konstruktors ankommt. Einstellung `this.button` an `null` gibt nichts wieder, was für ein Werkzeug nützlich ist, das nur in einigen Konfigurationen gilt.

Eine Sache, die man beachten sollte: `Tool`Konstruktoraufrufe `createButton()`, also muss alles, was Ihre Override-Bedürfnisse haben, von `this.editor`, nicht aus einem Feld, das Sie nach `super()`.

#### Der Dialoghelfer

`MarkdownEditor.modal` ist der Dialog, den der integrierte Link und die Bildtools verwenden, so dass ein Tool von Ihnen, das Eingaben sammelt, wie der Rest des Editors aussieht, anstatt ein eigenes Popup zu erfinden. Es gibt die `<dialog>` element, das bereits geöffnet ist, das Sie für Ihre Felder abfragen und mit `dialog.close()`.

<Snippet view="code">

```javascript
// (event, size classes, body HTML, aria label)
const dialog = MarkdownEditor.modal(event, 'fj:max-w-sm', '…', 'Embed');
```

</Snippet>

Übergeben Sie die `event` Ihre `applySyntax()` empfangen. Der Helfer liest es, um herauszufinden, von welchem Editor der Klick kam, so dass der Dialog innerhalb des Wrappers dieses Editors angehängt wird und sein Thema aufnimmt. Es ersetzt alle bereits in diesem Editor geöffneten Dialoge und entfernt sich selbst aus dem Dom, wenn es geschlossen wird, so dass es nichts zu bereinigen gibt.

#### Rendering Markdown selbst

Wenn Ihr Tool gerenderte Inhalte einbettet, z. B. einen Tooltip-Body, `editor.renderMarkdown()` erzeugt HTML genau wie die Vorschau und ehrt damit Ihre `renderer` und `sanitizer`.

<Snippet view="code">

```javascript
const html = editor.renderMarkdown('**bold** text');
```

</Snippet>

#### Eine Symbolleiste für den eigenen Textbereich

Wenn ein Dialog Rich-Text sammelt, geben Sie ihm die richtigen Formatierungswerkzeuge, anstatt sie neu zu erstellen. Die Symbolleiste ist an den Textbereich gebunden, den Sie passieren, Ihren `locale` zeichenfolgen werden vererbt, und es wird keine Vorschau-Schaltfläche hinzugefügt.

<Snippet view="code">

```javascript
const body = dialog.querySelector('textarea');
const bar = editor.createToolbar(body, ['bold', 'italic', 'strikethrough']);
dialog.querySelector('.body-toolbar').appendChild(bar);
```

</Snippet>

Dies verwaltet nicht die Lebensdauer der Symbolleiste. Die Schaltflächen werden mit dem Dialogfeld bereinigt, wenn es entfernt wird, aber wenn ein Werkzeug darin etwas seitenweit registriert, einen Dokumenten-Listener oder einen Timer, lassen Sie das selbst los, wenn das Dialogfeld geschlossen wird.

#### Übersetzung

Benutzerdefinierte Tools übersetzen wie integrierte Tools, die durch den Titel, den Sie ihnen gegeben haben, getastet werden.

### 📊 Fußzeile (Statusleiste)

Die Fußzeile befindet sich unterhalb des Editors und zeigt die **Zeile**, **Spalte** des Cursors, die **Zeichenanzahl ** des Dokuments und optional die **Wortanzahl**, die alle in Echtzeit aktualisiert werden. Es ist standardmäßig sichtbar und jeder Wert kann unabhängig umgeschaltet werden.

| `chars` | `boolean` | `true` | Zeigt die Gesamtzahl der Zeichen an. |
| `words` | `boolean` | `false` | Zeigt die Gesamtzahl der Wörter an. Standardmäßig ausgeschaltet: eingestellt auf `true` ermöglichen. |

</DocTable>

### Zwei Bearbeitungsmodi

**MarkdownEditor** bietet zwei verschiedene Möglichkeiten zum Schreiben und Formatieren Ihrer Inhalte. Sie können zwischen einer traditionellen syntaxorientierten Ansicht und einem modernen, visuell ausgerichteten Erlebnis wechseln.

-   `plain` (*Standard**): Eine saubere, leistungsstarke Markdown-Umgebung, in der Syntax (wie `**bold**` oder `# heading`) ist sichtbar. Ideal für Entwickler und Markdown-Puristen
-   `hybrid`: Ein WYSIWYG-inspiriertes Erlebnis, das Formatierungen (Fett, Kursiv, Überschriften) in Echtzeit während der Eingabe wiedergibt und gleichzeitig die zugrunde liegende Markdown-Struktur beibehält.

<Snippet view="code">

```javascript
// Default initialization (Plain Mode)
new MarkdownEditor('#markdown-editor');

// Explicit Plain Mode
new MarkdownEditor('#markdown-editor', {
    mode: 'plain'
});

// Hybrid (Visual) Mode
new MarkdownEditor('#markdown-editor', {
    mode: 'hybrid'
});
```

</Snippet>

#### Vorschau des Hybrid- und Normalmodus:

##### Hybridmodus

Visuelle Formatierungen werden während der Eingabe in Echtzeit gerendert.

<RawHtml html={"<textarea class=\"hybrid-markdown-editor mb-4\" rows=\"5\" placeholder=\"Start writing...\"># Hybrid mode markdown editor This will render visual styles immediately.</textarea>"} />

##### Einfacher Modus (Standard)

Konzentriert sich auf die reine Markdown-Syntax für ein unkompliziertes Erlebnis.

<RawHtml html={"<textarea class=\"plain-markdown-editor mb-4\" rows=\"5\" placeholder=\"Start writing...\"># Plain mode markdown editor This shows the raw **syntax**.</textarea>"} />

### 🌙 Thematisierung

**MarkdownEditor** erbt sein Thema automatisch von der umgebenden Seite: keine Konfiguration erforderlich. Der Herausgeber liest `data-theme` vom nächsten Vorfahren bei der Initialisierung, so dass es sofort mit dem Thema Ihrer Website synchronisiert bleibt.

#### Wie das Thema gelöst wird (Prioritätsreihenfolge)

1.  **`theme` Option**: explizite Überschreibung im Optionsobjekt übergeben
2.  **`data-theme` auf der `<textarea>`**: direkt auf das Element setzen
3.  **`data-theme` auf einem beliebigen Vorfahren**: z.B. `<html>`, `<body>`, oder ein Wrapper `<div>`

#### Verfügbare Themen

`'light'` (Standard), `'dark'`, `'snowberry'`, `'darkberry'`

##### Option 1, erben von `<html>` oder ein beliebiger Vorfahre (keine Konfiguration)

<Snippet view="code">

```html
<html data-theme="dark">
  ...
  <textarea id="markdown-editor"></textarea>
  <script>
    new MarkdownEditor('#markdown-editor'); // picks up dark automatically
  </script>
```

</Snippet>

##### Option 2: einstellen `data-theme` direkt am `<textarea>`

<Snippet view="code">

```html
<textarea id="markdown-editor" data-theme="dark"></textarea>
<script>
  new MarkdownEditor('#markdown-editor');
</script>
```

</Snippet>

##### Option 3: explizit `theme` Option (überschreibt alles)

<Snippet view="code">

```javascript
new MarkdownEditor('#markdown-editor', {
    theme: 'dark'
});
```

</Snippet>

### 🌐 Schnittstellensprache

Der eigene Text des Editors, Tooltips, Menüelemente, modale Felder und Schaltflächen sind standardmäßig Englisch. Pass a `locale` Objekt, um es zu übersetzen. Schlüssel sind die englischen Zeichenfolgen, so wie gettext funktioniert, sodass Sie nur auflisten, was Sie ändern möchten, und alles, was fehlt, wird auf Englisch zurückgesetzt.

`locale` Nimmt die Strings selbst, keinen Sprachcode. `locale: 'es'` hat keine Auswirkung und sagt dies auch in der Konsole. Importieren Sie stattdessen die gewünschte Sprache, damit niemand die Sprachen herunterlädt, die er nicht verwendet. Es hieß `labels` vor 2.0.0, und dieser Name funktioniert immer noch.

<Snippet view="code">

```javascript
new MarkdownEditor('#markdown-editor', {
    locale: {
        'Bold': 'Gras',
        'Italic': 'Italique',
        'Heading': 'Titre',
        'Link': 'Lien',
        'Image link': 'Lien de l\'image',
        'URL': 'URL',
        'Alt text': 'Texte alternatif',
        'Apply': 'Appliquer',
        'Uploading...': 'Téléversement...',
    },
});
```

</Snippet>

Dies ist neben rechts-nach-links geschriebenen Inhalten am wichtigsten. Arabisch, Urdu und Farsi werden für sich genommen korrekt angezeigt, aber eine Symbolleiste, in der immer noch „Fett“ über von rechts nach links geschriebenem Text steht, ist nur zur Hälfte übersetzt.

#### Die vollständige Liste der Zeichenfolgen

Es gibt 45 davon, und die Liste liegt dem Paket bei, sodass Sie nicht danach suchen müssen. Schlüssel und Werte sind identisch, es handelt sich also eher um eine Vorlage zum Kopieren als um eine Übersetzung.

<Snippet view="code">

```javascript
import template from 'markdown-text-editor/locale/template.js';
// { "Bold": "Bold", "Match case": "Match case", "{n} words": "{n} words", ... }
```

</Snippet>

Grafen tragen a `{n}` Platzhalter, damit Ihre Übersetzung darüber entscheidet, wo die Nummer eingefügt wird, anstatt sich an die englische Wortreihenfolge zu halten.

<Snippet view="code">

```javascript
locale: {
    '{n} words': '{n} palabras',
    '{n} chars': '{n} caracteres',
}
```

</Snippet>

#### Verwenden Sie Ihre eigenen Übersetzungen

`locale` nimmt ein einfaches Objekt, also liegt es an Ihnen, woher es kommt. Die meisten Projekte verfügen bereits über ein Übersetzungssystem, und die Einspeisung an den Editor sorgt dafür, dass der Wortlaut mit dem Rest der Benutzeroberfläche konsistent bleibt. In Django landen die Saiten in Ihrem `.po` Dateien mit allem anderen:

<Snippet view="code">

```python
from django.utils.translation import gettext as _

def edit(request):
    return render(request, 'edit.html', {
        'mte_strings': {
            'Bold': _('Bold'),
            'Italic': _('Italic'),
            'Apply': _('Apply'),
            'Uploading...': _('Uploading...'),
        },
    })
```

</Snippet>

<Snippet view="code">

```html
{{ mte_strings|json_script:"mte-strings" }}

<script type="module">
    const strings = JSON.parse(document.getElementById('mte-strings').textContent);
    new MarkdownEditor('#markdown-editor', { locale: strings });
</script>
```

</Snippet>

Ordnen Sie die Schlüssel mit einem clientseitigen Katalog wie i18next oder vue-i18n über Ihren zu `t()`:

<Snippet view="code">

```javascript
import template from 'markdown-text-editor/locale/template.js';

const strings = Object.fromEntries(
    Object.keys(template).map(key => [key, i18n.t(`editor.${key}`)])
);
```

</Snippet>

### 🏷 Variablen

Fügt ein Dropdown-Menü in der Symbolleiste zum Einfügen von Platzhaltern hinzu. Nützlich, wenn die Person, die ein Dokument schreibt, nicht der Entwickler ist, der die Platzhaltersyntax definiert hat, wie bei E-Mail-, Rechnungs- oder Vertragsvorlagen: Sie wählt einen lesbaren Namen und die richtige Syntax wird für sie eingefügt.

<Snippet view="code">

```javascript
new MarkdownEditor('#markdown-editor', {
    toolbar: ['bold', 'italic', 'link',
        { variables: [
            { label: 'Customer Name', value: '{{customer.name}}' },
            { label: 'Invoice No',    value: '{{invoice.number}}' }
        ]},
        'preview'
    ]
});
```

</Snippet>

Das Tool wird inline im konfiguriert `toolbar` Array, sodass die Position zwischen den anderen Schaltflächen Ihnen überlassen bleibt. Die Schaltfläche listet die Beschriftungen auf, und wenn Sie auf eine klicken, werden diese eingefügt `value` am Cursor und ersetzt jede Auswahl. Wenn die Liste leer ist, wird nichts gerendert.

#### Beispielwerte in der Vorschau

Ein Eintrag gegeben a `sample` zeigt dieses Beispiel in der Vorschau an, während der Textbereich den echten Platzhalter behält. Einträge ohne eins erscheinen wie geschrieben, Sie können also beides mischen.

<Snippet view="code">

```javascript
{ variables: [
    { label: 'Customer Name', value: '{{customer.name}}', sample: 'Hannes' },
    { label: 'Invoice No',    value: '{{invoice.number}}' }
]}

// textarea : Hi {{customer.name}}, invoice {{invoice.number}}
// preview  : Hi Hannes, invoice {{invoice.number}}
```

</Snippet>

#### Gruppierung

Geben Sie einen Eintrag ein `items` statt eines `value` um einen Abschnitt mit Überschrift darzustellen. Gruppierte und flache Einträge können in einer Liste gemischt werden.

<Snippet view="code">

```javascript
{ variables: [
    { label: 'Today', value: '{{today}}', sample: '10 September 2026' },
    { label: 'Customer', items: [
        { label: 'Name',  value: '{{customer.name}}',  sample: 'Hannes' },
        { label: 'Email', value: '{{customer.email}}', sample: 'hannes@example.com' }
    ]},
    { label: 'Invoice', items: [
        { label: 'Number', value: '{{invoice.number}}' }
    ]}
]}
```

</Snippet>

#### Wissenswertes

- **Der Editor löst niemals Variablen auf.** Er fügt Text ein und Ihre Anwendung ersetzt später reale Werte, normalerweise serverseitig. `sample` wirkt sich nur darauf aus, was in der Vorschau angezeigt wird.
- **Beschriftungen werden als einfacher Text angezeigt**, daher wird das Markup in einer Beschriftung nie gerendert.
- **Fehlerhafte Einträge werden übersprungen** statt ausgelöst, und die Schaltfläche wird überhaupt nicht gerendert, wenn nichts Verwendbares konfiguriert ist.

### 🖋 Benutzerdefinierter Renderer

Die Vorschau wird mit gerendert [markiert](https://marked.js.org) und desinfiziert mit [DOMPurify](https://github.com/cure53/DOMPurify). Beide können ausgetauscht werden. Verwenden Sie diese Option, wenn Ihre Anwendung Markdown bereits mit einer anderen Bibliothek rendert und Sie möchten, dass die Vorschau genau mit der Produktion übereinstimmt.

Bei beiden Optionen handelt es sich um einfache Funktionen, die einen String annehmen und zurückgeben, sodass jeder Parser und jedes Sanitizer funktioniert.

<Snippet view="code">

```javascript
import MarkdownIt from 'markdown-it';
import taskLists from 'markdown-it-task-lists';
import MarkdownEditor from 'markdown-text-editor';

const md = new MarkdownIt({ linkify: true, breaks: true }).use(taskLists);

new MarkdownEditor('#markdown-editor', {
    renderer: markdown => md.render(markdown)
});
```

</Snippet>

DOMPurify wird weiterhin auf der Ausgabe ausgeführt, sodass Sie den XSS-Schutz beibehalten, ohne etwas konfigurieren zu müssen.

#### Benutzerdefiniertes Desinfektionsmittel

Wird nur benötigt, wenn die Standardeinstellung etwas entfernt, das Ihr Renderer ausgibt. DOMPurify entfernt `<iframe>` Standardmäßig ist dies für Videoeinbettungen explizit zulässig. DOMPurify muss in Ihren eigenen Code importiert werden, da die mit dem Editor gebündelte Kopie intern ist.

<Snippet view="code">

```javascript
import DOMPurify from 'dompurify';

new MarkdownEditor('#markdown-editor', {
    renderer:  markdown => md.render(markdown),
    sanitizer: html => DOMPurify.sanitize(html, {
        ADD_TAGS: ['iframe'],
        ADD_ATTR: ['allow', 'allowfullscreen', 'frameborder']
    })
});
```

</Snippet>

Laden Sie DOMPurify mit einem Skript-Tag anstelle eines Bundlers zusammen mit dem Editor:

<Snippet view="code">

```html
<script src="https://cdn.jsdelivr.net/npm/dompurify"></script>
<script src="https://cdn.jsdelivr.net/npm/markdown-text-editor"></script>
```

</Snippet>

#### Wissenswertes

- **Nur Vorschau.** Die Live-Formatierung des Hybridmodus verwendet einen separaten internen Renderer und ist nicht betroffen.
- **Aufgabenlisten benötigen Plugin-Unterstützung.** Anklickbare Kontrollkästchen werden durch Suchen gefunden `input[type="checkbox"]` in der Ausgabe, daher ist ein Abschlag erforderlich `markdown-it-task-lists`. Der Editor protokolliert eine Warnung, wenn er die Aufgabenlistensyntax und keine Kontrollkästchen erkennt.
- **Beide müssen synchron sein** und einen String zurückgeben. Ein `async` Funktion schreibt `[object Promise]` in die Vorschau.
- **Der Austausch des Desinfektionsmittels ersetzt Ihren Schutz.** Eine Durchreiche wie z.B `html => html` deaktiviert die Bereinigung vollständig und ist nur für vollständig vertrauenswürdige Inhalte sicher.

```css
.markdown-editor-wrapper .toolbar {
    border-bottom: 2px solid oklch(60% 0.2 30);
}
```

</Snippet>

#### Ausrichtung auf einen Redakteur

Wenn Sie mehrere Redakteure auf einer Seite haben, zielen Sie auf einen von ihnen ab `data-editor`. Der Wrapper spiegelt seine ID wider `<textarea>`, Also `<textarea id="notes">` gibt dir `[data-editor="notes"]`. Die ID selbst bleibt also im Textbereich `getElementById` funktioniert weiter.

<Snippet view="code">

```css
/* one editor only */
[data-editor="notes"] {
    --border-radius: 0;
}
```

</Snippet>

### 🪟 Vollbild & Layering (Z-Index)

Im Vollbildmodus verwendet der Editor `z-index: 10000`, wodurch die Ebenen gelöscht werden, die die meisten UI-Frameworks für feste Header und Overlays reservieren. Wenn der Editor immer noch von einer festen Kopfzeile oder Seitenleiste abgedeckt wird, erhöhen Sie diesen Wert.

Überschreiben Sie es mit `--mte-fullscreen-z-index`. Der Wert gilt nur im Vollbildmodus und erbt. Wenn Sie ihn also auf einen beliebigen Vorfahren festlegen, werden alle darunter liegenden Editoren abgedeckt.

<Snippet view="code">

```css
/* every editor on the page */
.markdown-editor-wrapper {
    --mte-fullscreen-z-index: 20000;
}

/* one section only - the value inherits down */
#admin-panel {
    --mte-fullscreen-z-index: 20000;
}

/* a single editor, by its textarea id */
[data-editor="notes"] {
    --mte-fullscreen-z-index: 20000;
}
```

</Snippet>

### 🔒 Inhaltssicherheitsrichtlinie

Der Editor fügt keine Inline-Event-Handler hinzu, verwendet keine `eval`, und ab 2.0.0 injiziert nein `<style>` Element. Eine strikte Politik braucht nein `'unsafe-inline'` Ausnahme dafür, in beide Richtungen:

<Snippet view="code">

```
Content-Security-Policy: script-src 'self'; style-src 'self'
```

</Snippet>

Vor 2.0.0 wurde das CSS innerhalb des JavaScripts transportiert und beim Laden eingefügt, was eine Richtlinie ohne war `style-src 'unsafe-inline'` weigert sich ([#42](https://github.com/nezanuha/markdown-text-editor/issues/42)). Eine Nonce wurde in Betracht gezogen und verworfen: Sie hilft nur bei Richtlinien, die über eine Nonce und eine statisch gehostete Site verfügen `style-src 'self'` hat keinen Server, der pro Anfrage eine neue Nonce prägt. Durch die Verknüpfung des Stylesheets werden alle Richtlinien und nicht nur einige davon abgedeckt.

Eine Sache, die der Editor nicht kontrolliert, ist der Markdown, den Ihre Benutzer schreiben. DOMPurify bleibt bestehen `style` Attribute standardmäßig, also `<span style="color:red">` in einem Dokument überlebt in der Vorschau und einem strengen `style-src-attr` werde es melden. Ziehen Sie sie mit dem aus `sanitizer` Option, wenn Ihnen das wichtig ist:

<Snippet view="code">

```javascript
import DOMPurify from 'dompurify';

new MarkdownEditor('#markdown-editor', {
    sanitizer: html => DOMPurify.sanitize(html, { FORBID_ATTR: ['style'] }),
});
```

</Snippet>

## Inhalts-API

Eine der Kernstärken von **MarkdownEditor** besteht darin, dass es das zugrunde liegende behält `<textarea>` perfekt synchronisiert. Ganz gleich, ob Sie ein modernes JavaScript-Framework oder ein traditionelles Backend wie **Django, PHP oder Laravel** verwenden, der Workflow bleibt einfach und nativ.

### Inhalte lesen und schreiben

#### 1\. The Native Way (empfohlen)

Da der Editor einen Standardtextbereich erweitert, können Sie bekannte DOM-Methoden verwenden. Dies ist der schnellste Weg, mit Ihren Daten zu interagieren, ohne eine neue API zu erlernen.

<Snippet view="code">

```javascript
// Retrieve content via ID
const markdown = document.getElementById('markdown-editor').value;

// Set content via ID (The editor UI updates automatically)
document.getElementById('markdown-editor').value = "# New Heading Content";
```

</Snippet>

#### 2\. Verwenden einer Variablenreferenz

Wenn Sie einen Verweis auf das Textarea-Element haben, können Sie es direkt verwenden: Es ist keine bibliotheksspezifische API erforderlich.

<Snippet view="code">

```javascript
const textarea = document.getElementById('markdown-editor');

// Retrieve content
const markdown = textarea.value;

// Set content (the editor UI reflects this immediately)
textarea.value = "## Updated via JS";
```

</Snippet>

#### 3\. Festlegen des anfänglichen Inhalts serverseitig

Die empfohlene Methode zum Festlegen des anfänglichen Inhalts ist direkt im `<textarea>` HTML: Dies funktioniert natürlich mit jedem Backend-Framework (Django, Laravel, Rails, PHP usw.) und der Editor rendert es automatisch bei init.

<Snippet view="code">

```html
<!-- Recommended: set content server-side -->
<textarea id="markdown-editor"># Hello World</textarea>
```

</Snippet>

Um Inhalte zur Laufzeit zu lesen oder zu aktualisieren, verwenden Sie die native `textarea` Wert. Anruf `editor.render()` nach einem Update, um die Vorschau- und Hybridebene zu aktualisieren.

<Snippet view="code">

```javascript
const textarea = document.getElementById('markdown-editor');

// Read
const markdown = textarea.value;

// Update at runtime
textarea.value = '# New content';
editor.render();
```

</Snippet>

#### 4\. Abbau des Editors: `destroy()`

Anruf `editor.destroy()` um den Editor-DOM-Wrapper zu entfernen und das Original wiederherzustellen `<textarea>` an seine Position im Dokument. Nützlich in Single-Page-Anwendungen beim Unmounten einer Ansicht.

<Snippet view="code">

```javascript
const editor = new MarkdownEditor('#markdown-editor');

// Remove the editor and restore the plain textarea
editor.destroy();
```

</Snippet>

### Auf Veränderungen reagieren mit `onChange`

Übergeben Sie eine `onChange` Rückruf, um bei jeder Inhaltsänderung benachrichtigt zu werden. Empfängt die aktuelle Markdown-Zeichenfolge.

<Snippet view="code">

```javascript
const editor = new MarkdownEditor('#markdown-editor', {
    onChange(value) {
        console.log('Content changed:', value.length, 'characters');
    }
});
```

</Snippet>

#### Entwurf automatisch speichern mit `localStorage`

Gebrauch `onChange` um bei jedem Tastendruck einen Entwurf zu speichern. Stellen Sie es wieder her, indem Sie den Textbereich vorab ausfüllen, bevor Sie den Editor initialisieren.

<Snippet view="code">

```javascript
const DRAFT_KEY = 'my-page-draft';

// Restore saved draft before init (only if textarea starts empty)
const textarea = document.getElementById('markdown-editor');
const saved = localStorage.getItem(DRAFT_KEY);
if (saved && !textarea.value) textarea.value = saved;

// Save on every change
const editor = new MarkdownEditor('#markdown-editor', {
    onChange(value) {
        localStorage.setItem(DRAFT_KEY, value);
    }
});

// Clear draft after successful form submission
document.querySelector('form').addEventListener('submit', () => {
    localStorage.removeItem(DRAFT_KEY);
});
```

</Snippet>

### Formularübermittlung

Weil **MarkdownEditor** direkt auf dem nativen basiert `<textarea>`Es ist sofort mit jedem Backend-Framework (Django, Laravel, PHP, Ruby on Rails usw.) kompatibel.

Hier kommt die „Native-First“-Philosophie zum Tragen. Sie müssen die Daten vor dem Absenden eines Formulars nicht manuell synchronisieren. Der Browser behandelt den Editor genau wie ein Standard-Eingabefeld.

<Snippet view="code">

```html
<form method="POST" action="/api/submit">
  <textarea id="markdown-editor" name="content" class="h-48" rows="5">
    # Initial Content
  </textarea>

  <button type="submit">Submit to Server</button>
</form>

<script>
  // Just initialize it. That's it.
  new MarkdownEditor('#markdown-editor');
</script>
```

</Snippet>

<RawHtml html={"<p class=\"text-sm\"><strong>Notiz:</strong> Initialisierung des MarkdownEditor-Plugins erforderlich</p>"} />

Verwenden Sie einfach ein Standard-HTML `<form>`. Der `name` Das Attribut im Textbereich wird von Ihrem Server verwendet, um den Inhalt zu identifizieren.

##### 🚀 Warum es ein Game-Changer für Backends ist

Da der Herausgeber das Native bewahrt `<textarea>` Verhalten verarbeitet Ihr Server die Daten als Standardzeichenfolge. Es ist keine zusätzliche Logik erforderlich: Nein `preventDefault()` und kein Handbuch `FormData` Konstruktion.

##### 💡 Warum dies ein „Killer-Feature“ ist:

Die meisten Editoren (wie Quill, Editor.js, simpleMDE, easyMDE) speichern Daten in komplexen JSON-Strukturen. Wenn ein Entwickler diese verwendet, muss er sein Datenbankschema und seine Rendering-Logik neu schreiben.

Mit **MarkdownEditor** kann ein Entwickler eine alte Website durch eine einfache ersetzen `<textarea>` mit Ihrem Editor, und das **Backend weiß nicht einmal, dass es sich geändert hat**. Es erhält einfach den gleichen Rohtext wie immer, aber der Benutzer erhält ein zehnmal besseres Erlebnis.

<DocTable wrapper="overflow-x-auto w-full" table="table table-xs not-prose">

| Rahmen / Sprache | So greifen Sie auf den Markdown-Inhalt zu |
| --- | --- |
| PHP | `$_POST['content']` |
| Django  | `request.POST.get('content')` |
| Node.js (Express) | `req.body.content` |
| Laravel | `$request->input('content')` |
| Ruby on Rails | `params[:content]` |

</DocTable>

## 🖼️ Erweiterter Bild-Upload

Die native Handhabung von Bild-Uploads: Anstatt sich auf langsame, speicherintensive Base64-Strings zu verlassen, ist dies ein erheblicher Gewinn für Leistung und SEO.

### Einfügen und ablegen

Fügen Sie einen Screenshot ein oder ziehen Sie eine Bilddatei in den Editor und sie wird über denselben Endpunkt wie die Symbolleistenschaltfläche hochgeladen. Ein Platzhalter wird sofort angezeigt, sodass der Editor nie eingefroren aussieht, und er wird durch den tatsächlichen Pfad ersetzt, sobald der Upload erfolgt. Wenn der Upload fehlschlägt, wird der Platzhalter durch eine sichtbare Markierung ersetzt und verschwindet nicht lautlos.

Das braucht `uploadUrl` unten konfiguriert. Ohne sie führt das Einfügen eines Bilds zu nichts und der Editor protokolliert eine Warnung, die erklärt, was hinzugefügt werden soll, da die Alternative ein Base64-String in Ihrer Datenbank wäre.

Es werden mehrere Dateien gleichzeitig hochgeladen, sodass die Bilder in der Reihenfolge landen, in der sie eingegangen sind.

### Konfigurationsoptionen

Das Bildtool unterstützt a `fileInput` Konfiguration für direkte Server-Uploads.

-   `accept`: Definieren Sie ein Array zulässiger Bildformate (z. B. „webp“, „avif“).
-   `uploadUrl`: Geben Sie den Backend-Endpunkt an, an dem die `File` Das Objekt wird per gesendet `POST`
-   `params`: Optionales Objekt zum Senden zusätzlicher Daten (wie CSRF-Tokens, Benutzer-IDs oder Ordnernamen) zusammen mit der Bilddatei

### Anwendungsbeispiel (Vollständige Konfiguration)

<Snippet view="code">

```javascript
const options = {
  placeholder: 'Start writing...',
  toolbar: [
    'link',
    {
      image: {
        fileInput: {
            accept: ['webp', 'avif'], // restrict the image upload format
            uploadUrl: '/api/upload', // Your upload endpoint
            params: {
                _token: 'your_csrf_token_here', // Essential for Laravel/Django
                folder: 'blog_posts'
            }
        },
        // Supports boolean: true/false OR object: { required: true }
        altInput: { required: true }
      }
    },
    'preview'
  ],
}
const editor = new MarkdownEditor('#markdown-editor', options);
```

</Snippet>

### 📡 Serverintegration

#### Die Anfrage

Der Herausgeber sendet eine `POST` Anfrage als `multipart/form-data`. Standardmäßig umfasst es:

-   `image_file`: Das eigentliche Dateiobjekt
-   `image_alt`: Der vom Benutzer eingegebene Alternativtext
- ... plus alle in der definierten benutzerdefinierten Daten `params` Objekt

#### Die erforderliche Antwort

Um einen erfolgreichen Upload zu bestätigen und das Bild in den Editor einzufügen, **muss** Ihr Server die folgende JSON-Struktur zurückgeben:

<Snippet view="code">

```json
{
  "success": true,
  "image_path": "https://cdn.yourdomain.com/uploads/image.webp"
}
```

</Snippet>

**Hinweis**: Stellen Sie sicher, dass Sie den Schlüssel verwenden `image_path` für die URL des hochgeladenen Bildes.

Sie können auch zurückkehren `image_alt`, der nur dann als Vorschlag verwendet wird, wenn der Benutzer das Alt-Feld leer gelassen hat. Alles, was sie selbst eingegeben haben, gewinnt immer, sodass ein Server, der Alternativtext aus dem Dateinamen oder der Bilderkennung ableitet, ihn anbieten kann, ohne eine echte Beschreibung zu überschreiben.

<Snippet view="code">

```json
{
  "success": true,
  "image_path": "https://cdn.yourdomain.com/uploads/image.webp",
  "image_alt": "Two people looking at a laptop"
}
```

</Snippet>

Bei Misserfolg kehren Sie zurück `success: false` mit einem `error` oder `message` Zeichenfolge. Dieser Text wird dem Benutzer angezeigt, also machen Sie ihn zu etwas, auf das er reagieren kann.

### Bild-Alt-Text-Validierung (`altInput`)

Um sicherzustellen, dass Ihre Inhalte zugänglich und SEO-freundlich bleiben, erzwingt **MarkdownEditor** standardmäßig die Alt-Text-Validierung.

- **Standardverhalten**: Wenn `altInput` ist nicht definiert, der Standardwert ist `{ required: true }`
- **Barrierefreiheit erzwingen**: Benutzer können kein Bild einfügen, bis eine Alternativbeschreibung bereitgestellt wird

#### 1\. Standard (keine Konfiguration erforderlich)

<Snippet view="code">

```javascript
// Alt text is REQUIRED by default
image: {
  fileInput: { uploadUrl: '/api/upload' }
}
```

</Snippet>

#### 2\. Kurzschrift (Validierung deaktivieren)

Wenn Sie Bilder ohne Beschreibung zulassen möchten, setzen Sie einfach den booleschen Wert auf `false`.

<Snippet view="code">

```javascript
image: {
  altInput: false // Users can now skip the alt text field
}
```

</Snippet>

#### 3\. Objektbasiert (explizit)

<Snippet view="code">

```javascript
image: {
    altInput: {
        required: false // Disables alt text validation — users can skip the alt field
    }
}
```

</Snippet>

### Standardbildnutzung (Nr `fileInput`)

Wenn `fileInput` nicht konfiguriert ist, verwendet der Editor standardmäßig ein einfaches URL-basiertes Modal. Dies ist ideal, wenn Ihre Benutzer hauptsächlich auf externe Image-Hosts verlinken.

<Snippet view="code">

```javascript
const options = {
  toolbar: [
    'link',
    'image',
    'preview'
  ],
}
const editor = new MarkdownEditor('#markdown-editor', options);
```

</Snippet>

### 💡 Warum Parameter verwenden?

In Frameworks wie Laravel oder Django können Sie keine Dateien ohne CSRF-Token hochladen. Durch Hinzufügen `_token` zum `params` Objekt, Ihre Anfrage durchläuft die Sicherheits-Middleware des Backends nahtlos und behält die „Zero Logic“-Philosophie für Ihre serverseitigen Controller bei.

## 🔍 Suchen und Ersetzen

Im Editor ist ein integriertes Such- und Ersetzungsfeld verfügbar: Es ist keine Browsererweiterung oder ein separates Tool erforderlich.

- Drücken Sie `Ctrl + F` (oder `⌘ F`), um das Bedienfeld **Suchen** zu öffnen
- Drücken Sie `Ctrl + H` (oder `⌘ H`), um das Bedienfeld **Suchen und Ersetzen** zu öffnen
- Die Suche berücksichtigt **Groß- und Kleinschreibung** und zeigt einen Live-Match-Zähler an (z. B. *3 von 12*)
- Navigieren Sie durch Übereinstimmungen mit den Tasten **▲ / ▼** oder `Enter` / `Shift + Enter`
- **Ersetzen** ersetzt die aktuell hervorgehobene Übereinstimmung; **Alle ersetzen** ersetzt jedes Vorkommen auf einmal
- Drücken Sie `Escape` um das Bedienfeld zu schließen und den Fokus wieder auf den Editor zu richten

Das Bedienfeld schwebt in der oberen rechten Ecke des Editor-Inhaltsbereichs und unterbricht den Schreibvorgang nicht.

## 🔗 Links von einer eingefügten URL

Die Regel ist bewusst streng: nur ein Bare `http` oder `https` URLs ohne Leerzeichen werden auf diese Weise behandelt. Das Einfügen eines Satzes, der zufällig eine URL enthält, oder das Einfügen ohne Auswahl verhält sich wie ein gewöhnliches Einfügen.
