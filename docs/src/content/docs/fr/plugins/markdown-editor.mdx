Plugin d'édition de texte Markdown qui transforme une zone de texte native en une suite d'édition complète – aucune synchronisation requise. Modes WYSIWYG et Markdown simple, aperçu en direct, recherche et remplacement, prise en charge RTL, mode sombre. Fonctionne avec Django, Laravel, Rails, Node.js, PHP et n'importe quelle pile.

## Installation

#### NPM (bundles : Vite, webpack, Rollup, etc.)


</Snippet>

## La philosophie : « Les autochtones d'abord »

La plupart des éditeurs rompent avec le flux de travail Web standard. **MarkdownEditor** l'accepte. Parce qu'il se trouve directement au-dessus d'un `<textarea>`, vous n'avez pas besoin d'apprendre une nouvelle façon de gérer les données.

- **Aucune liaison de données nécessaire :** Fonctionne avec `<form method="POST">` hors de la boîte
- **Accès standard :** Utilisation `document.getElementById('editor').value` tout comme une entrée normale.
- **Backend Agnostic :** Fonctionne avec n'importe quel backend (Python, Node.js, PHP, etc.), tout comme un champ de formulaire normal

## MarkdownEditor et EasyMDE / SimpleMDE

La plupart des éditeurs de démarques JavaScript (EasyMDE, SimpleMDE, éditeurs basés sur CodeMirror) ** cachent votre `<textarea>`** et modifiez une copie, en écrivant le contenu lorsque le formulaire est soumis. Cela fonctionne jusqu'à ce que quelque chose d'autre ait besoin de la valeur : a `required` le champ sur lequel le navigateur ne peut pas se concentrer bloque entièrement la soumission, et `.value` ou `FormData` lire avant de soumettre renvoie une chaîne vide, ce qui brise les protections htmx, Turbo, la sauvegarde automatique et les modifications non enregistrées. **MarkdownEditor est différent** : il stylise la zone de texte que vous avez déjà et la laisse comme champ dans lequel vous tapez, de sorte que la valeur est correcte à tout moment.

| `.value` corriger avant de soumettre | ✅ | ❌ Vide jusqu'à ce que le formulaire soit soumis |
| Sérialise avec `FormData`, htmx, Turbo | ✅ | ❌ Nécessite la propre API de l'éditeur |

## Intégration du cadre

Parce que **MarkdownEditor** préserve le natif `<textarea>`, il s'intègre à tous les frameworks backend sans aucun code supplémentaire. Votre serveur reçoit le contenu de la démarque exactement comme il le ferait à partir de n'importe quel champ de formulaire standard. Pour React et Vue, il faut quelques lignes, couvertes à la fin de cette section.

### Django 

Ajouter un `class` dans votre widget de zone de texte et initialiser l'éditeur — `request.POST['content']` fonctionne sans étapes supplémentaires.

<Snippet view="code">

```python

    class Meta:
        model = Post
        fields = ['content']
        widgets = {
            'content': forms.Textarea(attrs={'class': 'markdown-editor'}),
        }
```

</Snippet>

```javascript
new MarkdownEditor('.markdown-editor');
// request.POST['content'] contains the markdown on submit
```

</Snippet>

### Réagir

Créez l'éditeur dans un effet et détruisez-le lors du démontage. Utilisez `defaultValue` au lieu de `value`: l'éditeur écrit directement dans la zone de texte, de sorte qu'une liaison contrôlée écraserait ce que l'utilisateur est en train de taper.

<Snippet view="code">

```javascript
import { useEffect, useRef } from 'react';
import MarkdownEditor from 'markdown-text-editor';

function MarkdownField({ name, defaultValue = '', onChange }) {
    const ref = useRef(null);

    useEffect(() => {
        const editor = new MarkdownEditor(ref.current, { onChange });
        return () => editor.destroy();
    }, []);

    return &lt;textarea ref={ref} name={name} defaultValue={defaultValue} /&gt;;
}
```

</Snippet>

Retour `editor.destroy()` de l'effet couvre également StrictMode, qui exécute des effets deux fois en cours de développement et laisserait sinon deux éditeurs sur une zone de texte. Le tableau de dépendances vide est délibéré : les options sont lues une fois lors de la création de l'éditeur, donc relancer l'effet le détruirait et le reconstruirait à chaque changement.

### Vue

Même idée. Définissez la valeur initiale une fois dans `onMounted` et ne lient pas `:value`, ou chaque frappe émise en retour à travers `v-model` écraserait la zone de texte.

<Snippet view="code">

```javascript
&lt;script setup&gt;
import { ref, onMounted, onBeforeUnmount } from 'vue';
import MarkdownEditor from 'markdown-text-editor';

const el = ref(null);
const props = defineProps({ modelValue: { type: String, default: '' } });
const emit = defineEmits(['update:modelValue']);
let editor = null;

onMounted(() => {
    el.value.value = props.modelValue;
    editor = new MarkdownEditor(el.value, {
        onChange: value =&gt; emit('update:modelValue', value)
    });
});

onBeforeUnmount(() =&gt; editor?.destroy());
&lt;/script&gt;

&lt;template&gt;&lt;textarea ref="el"&gt;&lt;/textarea&gt;&lt;/template&gt;
```

</Snippet>

Utilisé comme : `<MarkdownField v-model="content" />`. En clair, vous pouvez sauter `v-model` entièrement et lire la valeur de la zone de texte à la soumission, comme avec tout autre cadre.

## Configuration

Vous pouvez entièrement personnaliser le comportement et l'interface de l'éditeur en passant un `options` objet. Si vous omettez une option, la valeur **par défaut** est utilisée.

Les options sont lues une fois, lorsque l'éditeur est construit. Les modifier par la suite n'a aucun effet — appelez `destroy()` et créez un nouvel éditeur à la place.

<DocTable wrapper="overflow-x-auto w-full not-prose" table="table table-md">

| Propriété | Type | Par défaut | Finalité |
| --- | --- | --- | --- |
| `mode` | `string` | `'plain'` | Définit la vue initiale. Utilisez hybride pour une expérience WYSIWYG ou simple pour une syntaxe brute. |
| `placeholder` | `string` | `'Write...'` | Texte affiché lorsque l'éditeur est vide. |
| `toolbar` | `array` | `[...]` | Définit quels outils apparaissent et dans quel ordre. |
| `footer` | FAUX| objet | Tous visibles | Contrôle la barre d'état affichée sous l'éditeur. Réglez sur `false` pour le cacher entièrement, ou passer un objet pour basculer les statistiques individuelles. |
| `theme` | `string` | inherited | Définit explicitement le thème de l'éditeur (clair, foncé, mûre, mûre foncée). En cas d'omission, l'éditeur hérite `data-theme` de l'élément ancêtre le plus proche ou de la `<textarea>` tout seul.  |
| `minHeight` | `number` | `200` | Hauteur minimale en pixels à laquelle l'éditeur se rétrécit lorsque le contenu est court. Jumelle avec `maxHeight` pour définir la plage de croissance automatique. |
| `maxHeight` | `number` | `500` | Hauteur maximale en pixels que l'éditeur peut atteindre en mode non plein écran. Une fois que le contenu dépasse cette hauteur, une barre de défilement apparaît à l'intérieur de l'éditeur. L'éditeur dispose également d'une poignée de glissement afin que les utilisateurs puissent la redimensionner manuellement au-delà de cette limite. |
| `renderer` | `function` | `marked` | Remplace l'analyseur Markdown utilisé pour l'aperçu. Reçoit la chaîne de démarquage et doit renvoyer une chaîne HTML. |
| `sanitizer` | `function` | `DOMPurify` | Remplace le désinfectant HTML. Reçoit le code HTML rendu et doit renvoyer le code HTML sécurisé à afficher. |
| `onChange` | `function` | `undefined` | Le rappel a été déclenché à chaque modification de contenu — saisie, actions de la barre d'outils, annulation/rétablissement et continuation de la liste. Reçoit la chaîne de démarque actuelle comme seul argument. |

</DocTable>

##### Conseils 💡 de mise en œuvre :

-   **Réorganisation** : les boutons apparaissent dans l'ordre exact dans lequel vous les listez dans le tableau
-   **Suppression * * : il suffit d'omettre n'importe quelle touche (comme `image`) de la baie pour désactiver cette fonctionnalité entièrement pour l'utilisateur
-   ** Repli natif ** : si vous ne fournissez pas un `placeholder` dans JS, le plugin utilisera automatiquement le `placeholder` attribut de votre HTML `<textarea>`

### 📊 Pied de page (barre d'état)

Le pied de page se trouve sous l'éditeur et affiche la **ligne * *, la **colonne** du curseur, le ** nombre de caractères ** du document et éventuellement le ** nombre de mots ** — tous mis à jour en temps réel. Il est visible par défaut et chaque statistique peut être basculée indépendamment.

<DocTable wrapper="overflow-x-auto w-full not-prose" table="table table-md">

| Légende | Type | Par défaut | Description |
| --- | --- | --- | --- |
| `line` | `boolean` | `true` | Afficher le numéro de ligne actuel. |
| `col` | `boolean` | `true` | Afficher le numéro de colonne actuel. |
| `chars` | `boolean` | `true` | Afficher le nombre total de caractères. |
| `words` | `boolean` | `false` | Afficher le nombre total de mots. Désactivé par défaut — défini sur `true` activer / permettre |

</DocTable>

#### Exemples d'utilisation

<Snippet view="code">

```javascript
// Default — line, col, and chars visible
new MarkdownEditor('#editor');

// Disable the footer entirely
new MarkdownEditor('#editor', { footer: false });

// Hide only character count
new MarkdownEditor('#editor', { footer: { chars: false } });

// Hide line and column, keep character count
new MarkdownEditor('#editor', { footer: { line: false, col: false } });

// Show only line number
new MarkdownEditor('#editor', { footer: { col: false, chars: false } });

// Enable word count alongside the defaults
new MarkdownEditor('#editor', { footer: { words: true } });

// Show word count only
new MarkdownEditor('#editor', { footer: { line: false, col: false, chars: false, words: true } });
```

</Snippet>

### Modes 🔀 de modification

**MarkdownEditor** offre deux façons distinctes d'écrire et de formater votre contenu. Vous pouvez basculer entre une vue traditionnelle axée sur la syntaxe ou une expérience moderne et visuelle.

-   `plain` (**Par défaut**) : un environnement Markdown propre et performant où la syntaxe (comme `**bold**` ou `# heading`) est visible. Idéal pour les développeurs et les puristes de Markdown
-   `hybrid`: une expérience inspirée de WYSIWYG qui rend le formatage (gras, italique, titres) en temps réel au fur et à mesure que vous tapez, tout en conservant la structure Markdown sous-jacente.

<Snippet view="code">

```javascript
// Default initialization (Plain Mode)
new MarkdownEditor('#markdown-editor');

// Explicit Plain Mode
new MarkdownEditor('#markdown-editor', {
    mode: 'plain'
});

// Hybrid (Visual) Mode
new MarkdownEditor('#markdown-editor', {
    mode: 'hybrid'
});
```

</Snippet>

#### Aperçu du mode hybride et simple :

##### mode hybride

La mise en forme visuelle est rendue en temps réel pendant que vous tapez.

### Thématisation

**MarkdownEditor** hérite automatiquement de son thème à partir de la page environnante — aucune configuration requise. L'éditeur lit `data-theme` à partir de l'ancêtre le plus proche à l'initialisation, de sorte qu'il reste synchronisé avec le thème de votre site dès sa sortie de la boîte.

#### Comment le thème est résolu (ordre de priorité)

1.  **`theme` option** — remplacement explicite passé dans l'objet options
2.  **`data-theme` sur des `<textarea>`** — défini directement sur l'élément
3.  **`data-theme` sur n'importe quel ancêtre** — par exemple `<html>`, `<body>`, un papier d'emballage `<div>`

#### Thèmes disponibles

`'light'` (par défaut) `'dark'`, `'snowberry'`, `'darkberry'`

##### Option 1 — hériter DE `<html>` ou tout ancêtre (configuration zéro)

<Snippet view="code">

```html
<html data-theme="dark">
  ...
  <textarea id="markdown-editor"></textarea>
  <script>
    new MarkdownEditor('#markdown-editor'); // picks up dark automatically
  </script>
```

</Snippet>

##### Option 2 — set `data-theme` En bord de mer `<textarea>`

<Snippet view="code">

```html
<textarea id="markdown-editor" data-theme="dark"></textarea>
<script>
  new MarkdownEditor('#markdown-editor');
</script>
```

</Snippet>

##### Option 3 — explicite `theme` option (remplace tout)

<Snippet view="code">

```javascript
new MarkdownEditor('#markdown-editor', {
    theme: 'dark'
});
```

</Snippet>

```javascript
new MarkdownEditor('#markdown-editor', { theme: 'brand' });
```

### Variables

Ajoute une liste déroulante de barre d'outils pour insérer des espaces réservés. Utile lorsque la personne qui écrit un document n'est pas le développeur qui a défini la syntaxe de l'espace réservé, comme avec les modèles de courrier électronique, de facture ou de contrat : ils choisissent un nom lisible et la syntaxe correcte est insérée pour eux.

<Snippet view="code">

```javascript
new MarkdownEditor('#markdown-editor', {
    toolbar: ['bold', 'italic', 'link',
        { variables: [
            { label: 'Customer Name', value: '{{customer.name}}' },
            { label: 'Invoice No',    value: '{{invoice.number}}' }
        ]},
        'preview'
    ]
});
```

</Snippet>

L'outil est configuré en ligne dans le `toolbar` , de sorte que sa position parmi les autres boutons dépend de vous. Le bouton répertorie les étiquettes, et en cliquant sur l'une insère son `value` au niveau du curseur, en remplaçant toute sélection. Rien n'est rendu si la liste est vide.

#### Valeurs d'échantillon dans l'aperçu

Une entrée donnée à un `sample` affiche cet échantillon dans l'aperçu, tandis que la zone de texte conserve l'espace réservé réel. Les entrées sans en avoir une apparaissent comme écrites, vous pouvez donc mélanger les deux.

<Snippet view="code">

```javascript
{ variables: [
    { label: 'Customer Name', value: '{{customer.name}}', sample: 'Hannes' },
    { label: 'Invoice No',    value: '{{invoice.number}}' }
]}

// textarea : Hi {{customer.name}}, invoice {{invoice.number}}
// preview  : Hi Hannes, invoice {{invoice.number}}
```

</Snippet>

#### Groupement

Donnez une participation `items` au lieu d'un `value` pour rendre une section à en-tête. Les entrées groupées et plates peuvent être mélangées dans une liste.

<Snippet view="code">

```javascript
{ variables: [
    { label: 'Today', value: '{{today}}', sample: '10 September 2026' },
    { label: 'Customer', items: [
        { label: 'Name',  value: '{{customer.name}}',  sample: 'Hannes' },
        { label: 'Email', value: '{{customer.email}}', sample: 'hannes@example.com' }
    ]},
    { label: 'Invoice', items: [
        { label: 'Number', value: '{{invoice.number}}' }
    ]}
]}
```

</Snippet>

#### Bon à savoir

-   **L'éditeur ne résout jamais les variables.** Il insère du texte, et votre application remplace les valeurs réelles plus tard, généralement côté serveur. `sample` affecte uniquement ce que l'aperçu affiche.
-   **Les étiquettes sont affichées en texte brut **, de sorte que le balisage d'une étiquette n'est jamais rendu.
-   ** Les entrées mal formées sont ignorées** plutôt que jetées, et le bouton n'est pas rendu du tout lorsque rien d'utilisable n'est configuré.

### 🖋 Rendu personnalisé

L'aperçu est rendu avec [marqué](https://marked.js.org) et désinfecté avec [DOMPurify](https://github.com/cure53/DOMPurify). Les deux peuvent être remplacés. Utilisez cette option lorsque votre application rend déjà le markdown avec une autre bibliothèque et que vous souhaitez que l'aperçu corresponde exactement à la production.

Les deux options sont des fonctions simples qui prennent une chaîne et renvoient une chaîne, de sorte que tout analyseur syntaxique et tout désinfectant fonctionnent.

<Snippet view="code">

```javascript
import MarkdownIt from 'markdown-it';
import taskLists from 'markdown-it-task-lists';
import MarkdownEditor from 'markdown-text-editor';

const md = new MarkdownIt({ linkify: true, breaks: true }).use(taskLists);

new MarkdownEditor('#markdown-editor', {
    renderer: markdown => md.render(markdown)
});
```

</Snippet>

DOMPurify s'exécute toujours sur la sortie, de sorte que vous conservez la protection XSS sans rien configurer.

#### Désinfectant personnalisé

Seulement nécessaire lorsque la valeur par défaut supprime quelque chose que votre moteur de rendu émet. DOMPurify supprime `<iframe>` par défaut, les intégrations vidéo doivent donc être explicitement autorisées. DOMPurify doit être importé dans votre propre code, car la copie fournie avec l'éditeur est interne.

<Snippet view="code">

```javascript
import DOMPurify from 'dompurify';

new MarkdownEditor('#markdown-editor', {
    renderer:  markdown => md.render(markdown),
    sanitizer: html => DOMPurify.sanitize(html, {
        ADD_TAGS: ['iframe'],
        ADD_ATTR: ['allow', 'allowfullscreen', 'frameborder']
    })
});
```

</Snippet>

À l'aide d'une balise de script au lieu d'un bundler, chargez DOMPurify à côté de l'éditeur :

<Snippet view="code">

```html
<script src="https://cdn.jsdelivr.net/npm/dompurify"></script>
<script src="https://cdn.jsdelivr.net/npm/markdown-text-editor"></script>
```

</Snippet>

#### Bon à savoir

-   **Aperçu uniquement.** La mise en forme en direct du mode hybride utilise un moteur de rendu interne distinct et n'est pas affectée.
-   ** Les listes de tâches nécessitent la prise en charge des plugins.** Les cases à cocher cliquables sont trouvées en recherchant `input[type="checkbox"]` dans la sortie, donc markdown-it doit `markdown-it-task-lists`. L'éditeur enregistre un avertissement s'il détecte la syntaxe de la liste des tâches et aucune case à cocher.
-   **Les deux doivent être synchrones** et renvoyer une chaîne. Une `async` écritures de fonction `[object Promise]` Aperçu. 
-   **Le remplacement du désinfectant remplace votre protection.** Une transmission telle que `html => html` désactive entièrement la désinfection et n'est sans danger que pour le contenu entièrement fiable.

#### Cibler un éditeur

Avec plusieurs éditeurs sur une page, ciblez l'un d'entre eux avec `data-editor`. L'emballage reflète l'identifiant de son `<textarea>`Donc `<textarea id="notes">` vous donne: `[data-editor="notes"]`. L'ID lui-même reste sur la zone de texte, donc `getElementById` Il continue à travailler.

### 🪟 Plein écran et superposition (z-index)

En plein écran, l'éditeur utilise `z-index: 10000`, ce qui efface les couches que la plupart des cadres d'interface utilisateur réservent pour les en-têtes fixes et les superpositions. Si un en-tête ou une barre latérale fixe couvre toujours l'éditeur, augmentez cette valeur.

Remplacez-le par `--mte-fullscreen-z-index`. La valeur ne s'applique qu'en plein écran, et elle hérite, donc la définir sur n'importe quel ancêtre couvre tous les éditeurs en dessous.

<Snippet view="code">

```css
/* every editor on the page */
.markdown-editor-wrapper {
    --mte-fullscreen-z-index: 20000;
}

/* one section only - the value inherits down */
#admin-panel {
    --mte-fullscreen-z-index: 20000;
}

/* a single editor, by its textarea id */
[data-editor="notes"] {
    --mte-fullscreen-z-index: 20000;
}
```

</Snippet>

## API de contenu

L'une des principales forces de **MarkdownEditor** est qu'il conserve le sous-jacent `<textarea>` parfaitement synchronisé. Que vous utilisiez un framework JavaScript moderne ou un backend traditionnel comme **Django, PHP ou Laravel**, le flux de travail reste simple et natif.

### Lecture et écriture de contenu

#### 1\. The Native Way (Recommandé)

Étant donné que l'éditeur améliore une zone de texte standard, vous pouvez utiliser des méthodes DOM familières. C'est le moyen le plus rapide d'interagir avec vos données sans apprendre une nouvelle API.

<Snippet view="code">

```javascript
// Retrieve content via ID
const markdown = document.getElementById('markdown-editor').value;

// Set content via ID (The editor UI updates automatically)
document.getElementById('markdown-editor').value = "# New Heading Content";
```

</Snippet>

#### 2\. Utilisation d'une référence de variable

Si vous avez une référence à l'élément textarea, vous pouvez l'utiliser directement — aucune API spécifique à la bibliothèque n'est nécessaire.

<Snippet view="code">

```javascript
const textarea = document.getElementById('markdown-editor');

// Retrieve content
const markdown = textarea.value;

// Set content (the editor UI reflects this immediately)
textarea.value = "## Updated via JS";
```

</Snippet>

#### 3\. Définition du contenu initial côté serveur

La façon recommandée de définir le contenu initial est directement dans le `<textarea>` HTML — cela fonctionne naturellement avec tous les frameworks backend (Django, Laravel, Rails, PHP, etc.) et l'éditeur le rend automatiquement sur init.

<Snippet view="code">

```html
<!-- Recommended: set content server-side -->
<textarea id="markdown-editor"># Hello World</textarea>
```

</Snippet>

Pour lire ou mettre à jour le contenu au moment de l'exécution, utilisez le mode natif `textarea` valeur. Appeler `editor.render()` après une mise à jour pour actualiser l'aperçu et la couche hybride.

<Snippet view="code">

```javascript
const textarea = document.getElementById('markdown-editor');

// Read
const markdown = textarea.value;

// Update at runtime
textarea.value = '# New content';
editor.render();
```

</Snippet>

#### 4\. Démontage de l'éditeur — `destroy()`

Appel `editor.destroy()` pour retirer le wrapper DOM de l'éditeur et restaurer l'original `<textarea>` à sa position dans le document. Utile dans les applications d'une seule page lors du démontage d'une vue.

<Snippet view="code">

```javascript
const editor = new MarkdownEditor('#markdown-editor');

// Remove the editor and restore the plain textarea
editor.destroy();
```

</Snippet>

### Réagir aux changements avec `onChange`

Passer un `onChange` le rappel doit être notifié à chaque modification de contenu. Reçoit la chaîne de démarque actuelle.

<Snippet view="code">

```javascript
const editor = new MarkdownEditor('#markdown-editor', {
    onChange(value) {
        console.log('Content changed:', value.length, 'characters');
    }
});
```

</Snippet>

#### Ébauchez l'enregistrement automatique avec `localStorage`

Utilisation `onChange` pour enregistrer un brouillon à chaque frappe. Restaurez-le en pré-remplissant la zone de texte avant d'initialiser l'éditeur.

<Snippet view="code">

```javascript
const DRAFT_KEY = 'my-page-draft';

// Restore saved draft before init (only if textarea starts empty)
const textarea = document.getElementById('markdown-editor');
const saved = localStorage.getItem(DRAFT_KEY);
if (saved && !textarea.value) textarea.value = saved;

// Save on every change
const editor = new MarkdownEditor('#markdown-editor', {
    onChange(value) {
        localStorage.setItem(DRAFT_KEY, value);
    }
});

// Clear draft after successful form submission
document.querySelector('form').addEventListener('submit', () => {
    localStorage.removeItem(DRAFT_KEY);
});
```

</Snippet>

### Soumission du formulaire

Parce que **MarkdownEditor* * est construit directement sur le natif `<textarea>`, il est compatible avec tous les frameworks backend (Django, Laravel, PHP, Ruby on Rails, etc.) dès la sortie de la boîte.

C'est là que la philosophie « Native-First » brille. Vous n'avez pas besoin de synchroniser manuellement les données avant d'envoyer un formulaire. Le navigateur traite l'éditeur exactement comme un champ de saisie standard.

<Snippet view="code">

```html
<form method="POST" action="/api/submit">
  <textarea id="markdown-editor" name="content" class="h-48" rows="5">
    # Initial Content
  </textarea>

  <button type="submit">Submit to Server</button>
</form>

<script>
  // Just initialize it. That's it.
  new MarkdownEditor('#markdown-editor');
</script>
```

</Snippet>

<RawHtml html={"<p class=\"text-sm\"><strong>Remarque :</strong> Initialisation du plugin MarkdownEditor obligatoire</p>"} />

Il suffit d'utiliser un code HTML standard `<form>`Le `name` attribut sur la zone de texte est ce que votre serveur utilisera pour identifier le contenu.

##### 🚀 Pourquoi c'est un changeur de jeu pour les backends

Puisque l'éditeur préserve le natif `<textarea>` comportement, votre serveur gère les données comme une chaîne standard. Il n'y a aucune logique supplémentaire requise - non `preventDefault()` et pas de manuel `FormData` la constitution.

##### 💡 Pourquoi il s'agit d'une « fonctionnalité tueuse » :

La plupart des éditeurs (comme Quill, Editor.js, simpleMDE, easyMDE) enregistrent les données dans des structures JSON complexes. Si un développeur les utilise, il doit réécrire son schéma de base de données et sa logique de rendu.

Avec **MarkdownEditor**, un développeur peut prendre un ancien site Web, remplacer un simple `<textarea>` avec votre éditeur, et le **backend ne sait même pas qu'il a changé**. Il reçoit juste le même texte brut qu'il a toujours fait, mais l'utilisateur obtient une expérience 10 fois meilleure.

<DocTable wrapper="overflow-x-auto w-full" table="table table-xs not-prose">

| Cadre / Langue | Comment accéder au contenu Markdown |
| --- | --- |
| PHP | `$_POST['content']` |
| Django  | `request.POST.get('content')` |
| Node.js (Express) | `req.body.content` |
| Laravel | `$request->input('content')` |
| Ruby on Rails | `params[:content]` |

</DocTable>

## Téléchargement d'image 🖼️ avancé

La gestion des téléchargements d'images en mode natif - plutôt que de compter sur des chaînes Base64 lentes et lourdes de mémoire - est une victoire significative à la fois pour la performance et le référencement.

### Options de configuration

L'outil d'image prend en charge un `fileInput` configuration pour gérer les téléchargements directs du serveur.

-   `accept`: définissez un tableau de formats d'image autorisés (par exemple, « webp », « avif »)
-   `uploadUrl`: spécifiez le point de terminaison principal où le `File` l'objet sera envoyé via `POST`
-   `params`: objet facultatif pour envoyer des données supplémentaires (comme des jetons CSRF, des ID utilisateur ou des noms de dossiers) à côté du fichier image

### Exemple d'utilisation (configuration complète)

<Snippet view="code">

```javascript
const options = {
  placeholder: 'Start writing...',
  toolbar: [
    'link',
    {
      image: {
        fileInput: {
            accept: ['webp', 'avif'], // restrict the image upload format
            uploadUrl: '/api/upload', // Your upload endpoint
            params: {
                _token: 'your_csrf_token_here', // Essential for Laravel/Django
                folder: 'blog_posts'
            }
        },
        // Supports boolean: true/false OR object: { required: true }
        altInput: { required: true }
      }
    },
    'preview'
  ],
}
const editor = new MarkdownEditor('#markdown-editor', options);
```

</Snippet>

### Intégration 📡 de serveur

#### Demande d’assignation

L'éditeur envoie un `POST` demande en tant que `multipart/form-data`. Par défaut, il comprend :

-   `image_file`: l'objet de fichier réel
-   `image_alt`: le texte alternatif saisi par l'utilisateur
-   ...plus toutes les données personnalisées définies dans le `params` objet

#### Le délai d’intervention requis;

Pour confirmer un téléchargement réussi et insérer l'image dans l'éditeur, votre serveur **doit** renvoyer la structure JSON suivante :

<Snippet view="code">

```json
{
  "success": true,
  "image_path": "https://cdn.yourdomain.com/uploads/image.webp"
}
```

</Snippet>

**Remarque** : assurez-vous d'utiliser la clé `image_path` pour l'URL de l'image téléchargée.

### Validation du texte alternatif de l'image (`altInput`)

Pour vous assurer que votre contenu reste accessible et SEO-friendly, **MarkdownEditor** applique la validation de texte alternatif par défaut.

-   ** Comportement par défaut ** : si `altInput` n'est pas défini, il est défini par défaut sur `{ required: true }`
-   **Appliquer l'accessibilité** : les utilisateurs seront empêchés d'insérer une image jusqu'à ce qu'une description alternative soit fournie

#### 1\. Par défaut (Aucune configuration requise)

<Snippet view="code">

```javascript
// Alt text is REQUIRED by default
image: {
  fileInput: { uploadUrl: '/api/upload' }
}
```

</Snippet>

#### 2\. Sténographie (Désactiver la validation)

Si vous souhaitez autoriser les images sans description, définissez simplement le booléen sur `false`.

<Snippet view="code">

```javascript
image: {
  altInput: false // Users can now skip the alt text field
}
```

</Snippet>

#### 3\. Basé sur des objets (explicite)

<Snippet view="code">

```javascript
image: {
    altInput: {
        required: false // Disables alt text validation — users can skip the alt field
    }
}
```

</Snippet>

### Utilisation standard de l'image (Non `fileInput`)

Si `fileInput` n'est pas configuré, l'éditeur utilise par défaut un simple modal basé sur une URL. C’est idéal si vos utilisateurs établissent principalement des liens vers des hôtes d’images externes.

<Snippet view="code">

```javascript
const options = {
  toolbar: [
    'link',
    'image',
    'preview'
  ],
}
const editor = new MarkdownEditor('#markdown-editor', options);
```

</Snippet>

### 💡 Pourquoi utiliser des paramètres ?

Dans des frameworks comme Laravel ou Django, vous ne pouvez pas télécharger de fichiers sans jeton CSRF. En ajoutant `_token` au `params` object, votre demande passera par le middleware de sécurité du backend de manière transparente, en conservant la philosophie « Zero Logic » pour vos contrôleurs côté serveur.

## 🔍 Rechercher et remplacer

Un panneau de recherche et de remplacement intégré est disponible dans l’éditeur – aucune extension de navigateur ni outil séparé n’est nécessaire.

-   Presse `Ctrl + F` (ou `⌘ F`) pour ouvrir le panneau **Rechercher**
-   Presse `Ctrl + H` (ou `⌘ H`) pour ouvrir le panneau **Rechercher et remplacer**
- La recherche est **insensible à la casse** et affiche un compteur de correspondances en direct (par exemple *3 sur 12*)
- Parcourez les matchs avec les boutons **▲ / ▼** ou `Enter` / `Shift + Enter`
- **Remplacer** remplace la correspondance actuelle en surbrillance ; **Remplacer tout** remplace chaque occurrence à la fois
-   Presse `Escape` pour fermer le panneau et redonner le focus à l'éditeur

Le panneau flotte dans le coin supérieur droit de la zone de contenu de l'éditeur et n'interrompt pas l'écriture.

```javascript
const editor = new MarkdownEditor('#markdown-editor', {

        chars: true,
        words: true,

    onChange(value) {

            }

        'link', 'undo', 'redo', 'indent', 'outdent', 'preview'
```
